# Testing Rules

## 1. 기본 원칙

- 요구사항을 기준으로 테스트를 작성한다.
- 정상 케이스와 예외 케이스를 모두 검증한다.
- 테스트 결과를 실제로 확인한다.
- 테스트하지 않은 항목을 통과했다고 보고하지 않는다.
- 테스트는 반복 실행 가능해야 한다.
- 외부 시스템에 의존하는 테스트는 적절히 격리한다.

## 2. 테스트 종류

### Unit Test
- 개별 함수와 비즈니스 로직을 검증한다.
- 정상 입력과 잘못된 입력을 검증한다.
- 경계값을 검증한다.
- 외부 의존성은 필요한 경우 Mock 처리한다.

### Integration Test
- 여러 모듈 간 연동을 검증한다.
- Service와 Repository의 연동을 확인한다.
- 실제 DB와의 데이터 처리 결과를 검증한다.
- 트랜잭션 및 예외 상황을 검증한다.

### E2E Test
- 사용자의 실제 업무 흐름을 검증한다.
- 화면부터 API, DB까지 전체 흐름을 확인한다.
- 인증 및 권한에 따른 접근을 검증한다.
- 주요 업무 시나리오를 검증한다.

## 3. 테스트 케이스 작성

각 기능에 대해 다음 항목을 고려한다.

- 정상 처리
- 필수값 누락
- 잘못된 입력값
- 존재하지 않는 데이터
- 중복 데이터
- 권한이 없는 사용자
- 이미 처리된 요청
- 동시 요청
- DB 오류
- 외부 API 오류
- 경계값 및 최대 입력값

모든 항목을 무조건 테스트할 필요는 없으며 기능의 위험도와 요구사항에 따라 선택한다.

## 4. 테스트 명명 규칙

테스트 이름은 검증 목적을 명확하게 표현한다.

예시:

- shouldReturnUserWhenUserExists
- shouldThrowErrorWhenUserDoesNotExist
- shouldRejectDuplicateApproval
- shouldPreventUnauthorizedAccess

## 5. Backend 테스트 규칙

- Controller의 요청 및 응답을 검증한다.
- Service의 비즈니스 로직을 검증한다.
- DTO Validation을 검증한다.
- 권한 검증을 수행한다.
- DB 저장 및 수정 결과를 확인한다.
- 트랜잭션 Rollback을 검증한다.
- 중복 요청과 동시성 문제를 검증한다.

## 6. Frontend 테스트 규칙

- 화면이 정상적으로 렌더링되는지 확인한다.
- 사용자 입력값 검증을 확인한다.
- 버튼 및 이벤트 동작을 확인한다.
- API 성공 및 실패 응답을 확인한다.
- Loading 및 Empty 상태를 확인한다.
- Error 상태를 확인한다.
- 권한에 따른 화면 접근을 확인한다.
- 주요 사용자 흐름을 검증한다.

## 7. DB 테스트 규칙

- 데이터 저장이 정상적으로 이루어지는지 확인한다.
- 수정 및 삭제가 정상적으로 이루어지는지 확인한다.
- FK 제약조건이 작동하는지 확인한다.
- UNIQUE 제약조건이 작동하는지 확인한다.
- NULL 제약조건이 작동하는지 확인한다.
- 트랜잭션 Rollback을 확인한다.
- 중복 데이터 저장을 방지하는지 확인한다.
- 동시 수정 및 삭제 상황을 검증한다.

## 8. 테스트 데이터 관리

- 테스트 데이터는 실제 운영 데이터와 분리한다.
- 테스트 실행 전후 데이터 상태를 관리한다.
- 테스트 간 데이터 의존성을 최소화한다.
- 테스트 종료 후 불필요한 데이터를 정리한다.
- 테스트 데이터는 재현 가능하도록 구성한다.
- 개인정보를 사용하지 않는다.

## 9. 테스트 실행 규칙

작업 완료 후 프로젝트에 설정된 명령어를 확인하고 실행한다.

필요한 경우 다음 검증을 수행한다.

- Type Check
- Lint
- Unit Test
- Integration Test
- E2E Test
- Build

실행하지 못한 테스트가 있다면 그 이유를 보고한다.

## 10. 실패 처리

- 실패한 테스트를 임의로 삭제하지 않는다.
- 테스트 기대값을 실제 구현에 맞춰 무조건 변경하지 않는다.
- 오류 원인을 분석한다.
- 요구사항과 구현 중 어느 쪽이 잘못되었는지 확인한다.
- 테스트 실패를 해결한 후 재실행한다.
- 환경 문제와 코드 문제를 구분한다.

## 11. QA 보고서

테스트 완료 후 다음 내용을 보고한다.

1. 테스트 대상 기능
2. 테스트 환경
3. 실행한 테스트 종류
4. 전체 테스트 수
5. 성공한 테스트 수
6. 실패한 테스트 수
7. 실패한 테스트의 원인
8. 수정한 내용
9. 미검증 항목
10. 최종 품질 평가

## 12. 완료 기준

- 핵심 요구사항을 검증했는가?
- 정상 및 예외 케이스를 확인했는가?
- 기존 기능에 회귀 문제가 없는가?
- 테스트가 반복 실행 가능한가?
- 실제 실행 결과가 확인되었는가?
- 미검증 항목이 명확하게 보고되었는가?
