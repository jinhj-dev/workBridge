# leave-calendar 사용자 결정 항목

## 확정 (사용자 승인 피드백 반영)

| ID | 항목 | 결정 | 출처 |
|---|---|---|---|
| D1 | 공개 범위 | **전원(ADMIN·EMPLOYEE) 동일하게 공개. 상세는 社員名·所属部署만** | 사용자 답변 |
| D2 | 집계 상태 | **APPROVED만** (PENDING·REJECTED·CANCELLED 제외) | 사용자 답변 |
| D3 | 주말·공휴일 | **토·일 제외**, 공휴일은 데이터가 없어 평일 취급 | 사용자 답변 |
| D4 | 비활성 사원 | 활성 사원만(FR-DASH-001 "휴가 인원"과 같은 기준) | 권장안 유지(무응답) |
| D5 | 상세 조회 방식 | 월 집계 API + 날짜 상세 API(1일분) | 권장안 유지(무응답) |
| D6 | 상세 표시 | 기존 `Modal` | 권장안 유지(무응답) |
| D7 | 주 시작 요일 | 일요일 시작(日~土) | 권장안 유지(무응답) |
| D8 | 반차 여부 표시 | **B: 반차만 표시**(「午前半休」「午後半休」). 그 외 종류는 미표시 | 사용자 승인 |
| D9 | ADMIN 사유 표시 | **A: 전원 동일**(ADMIN도 사유 미표시) | 사용자 승인 |

### D1 반영 내용
- API 경로는 `/admin`이 아닌 `/dashboard/*`(인증 사용자 공용, `@AdminOnly` 없음). 대시보드의 사용자 공용 API는 지금까지 없었으므로(개인 영역은 `/attendance/today`·`/leaves/*` 조합) `DashboardModule`에 사용자용 컨트롤러를 새로 둔다. `/leaves/calendar`는 기존 `GET /leaves/:id`와 경로가 겹치므로 쓰지 않는다.
- 최소 노출: 상세 API 응답은 `{ userId, name, departmentName, halfDay }`만(halfDay는 D8). 사유·휴가 종류 enum·기간·상태·사원번호·승인자·휴가 ID는 **응답에도 포함하지 않는다**(화면에서 숨기는 것이 아니라 서버에서 내보내지 않음).
- **요청 원문과 달라진 점**: 8-3은 표시 항목으로 申請理由(신청 사유)를 들었으나 사용자 결정으로 **제외**한다.
- FR-LEAVE-005와의 관계: FR-LEAVE-005가 제한하는 "휴가 상세"는 Leave 객체(사유·종류·기간·승인·처리 정보, API-LEAVE-004)다. 캘린더는 "어느 날 누가 승인된 휴가로 부재인지"(이름·부서·날짜)만 공개하므로 휴가 상세 열람에 해당하지 않는다고 해석한다. 다만 타인 정보의 새 공개 정책이므로 문서 반영 시 FR-DASH-001에 공개 범위를 명문화하고 FR-LEAVE-005에 "휴가 캘린더의 이름·부서 공개는 예외가 아니다(상세 아님)"라는 보충을 단다.

### D2 반영 내용
- 월 API는 날짜별 `count` 하나만 반환(`approvedCount`·`pendingCount` 구분 없음). 화면의 "承認待ち n名" 보조 표시는 없앤다.
- 상세 목록도 APPROVED만이므로 상태 배지는 표시하지 않는다.
- **요청 원문과 달라진 점**: 8-3 "휴가 상태도 함께 확인할 수 있도록 표시"는 APPROVED만 노출하므로 **적용하지 않는다**. 8-2 "휴가 상태별 집계 기준 명확화"는 "APPROVED만"으로 충족한다.
- 승인 대기 건은 캘린더에 나타나지 않는다. 승인 후 다시 조회하면 반영된다(대시보드에서 승인하면 캘린더를 자동으로 다시 조회).

### D8 반영 내용 (반차만 표시)
- 응답 필드는 휴가 종류 enum을 그대로 내보내지 않고 `halfDay: 'AM' | 'PM' | null` 하나만 추가한다(ANNUAL·SPECIAL·OTHER의 구분은 노출하지 않음).
- 판정(사원·날짜 단위, 그날 APPROVED 휴가 전체 기준):
  - HALF_AM만 → `'AM'`(「午前半休」) / HALF_PM만 → `'PM'`(「午後半休」)
  - HALF_AM + HALF_PM 둘 다 → `null`(하루 휴가와 같음, 라벨 없이 1행) — 메인 결정
  - 종일 휴가(ANNUAL·SPECIAL·OTHER)가 하나라도 있으면 → `null`(종일+반차 겹침 포함. 신청 시 중복 검사로 보통 생기지 않지만 방어적으로 처리)
- 배지 인원 계산은 변하지 않는다(반차도 1명).

### D9 반영 내용
- ADMIN·EMPLOYEE 응답·화면 동일. ADMIN이 사유가 필요하면 기존 승인 화면·휴가 상세 모달(API-LEAVE-004)을 쓴다.
