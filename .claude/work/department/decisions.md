## Q4-B에 따른 후속 결정 (설계 반영, 아래 Q9·Q10은 사용자 확인 필요)
- 비활성 사원 이동 대상: 未所属(code `UNASSIGNED`, name `未所属`). 마이그레이션과 seed가 **항상** 만든다(이전 설계의 "NULL 사원이 있을 때만"에서 변경)
- 시스템 부서 구분: 고정 코드 `UNASSIGNED` 상수(플래그 컬럼 추가 없음). 응답에 `isSystem`을 계산해 넣어 프론트가 코드를 하드코딩하지 않게 한다
- `memberCount` = 활성 사원 수. 화면 삭제 가능 판단도 이 값. 비활성 수는 `inactiveMemberCount`로 별도 제공
- 삭제 확인 모달에 비활성 이동 안내를 넣는다(`inactiveMemberCount > 0`일 때만)
- 비활성 사원 이동으로 "퇴직 당시 부서" 정보는 남지 않는다(Q4-B의 결과로 수용)

| # | 항목 | 선택지 | 권장 |
|---|---|---|---|
| Q9 | 未所属 부서 보호 범위 | A. 수정·삭제 모두 금지 / B. 코드 변경·삭제만 금지, 이름 변경 허용 / C. 보호 없음 | **A** — 검사 1곳(id의 code가 UNASSIGNED면 409)으로 끝나고, 화면도 해당 행의 [編集][削除]를 숨기면 됨. C는 삭제 시 이동 대상이 사라짐 |
| Q10 | 활성 사원을 未所属에 배정 허용 | A. 허용 / B. 사원 API에서 금지(400) | **A** — 마이그레이션이 기존 활성 사원(초기 ADMIN 등)을 未所属에 넣으며, 재배정 전 임시 소속으로 필요. 사원 관리 구현 시의 규칙이므로 이번 구현 영향 없음 |
현재 설계는 Q9-A, Q10-A로 작성되어 있다.

## 문구 (일본어)
- 삭제 불가: 「所属する社員が存在するため、部署を削除できません。」
- 시스템 부서 보호: 「未所属部署は変更・削除できません。」
- 삭제 확인 안내: 「無効の社員 {n} 名は「未所属」部署に移動されます。」
