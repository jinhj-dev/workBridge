## Screen Access Rules

- 비로그인: 로그인하지 않은 사용자. 로그인한 사용자가 접근하면 `/dashboard`로 이동한다.
- 공통: 로그인한 모든 사용자(ADMIN, EMPLOYEE)
- 관리자: `role = ADMIN`인 사용자만. `/admin/*` 경로는 모두 관리자 전용이다.
- 승인자는 별도 권한이 아니다. SCR-005(SCR-004 承認 탭)에서 본인에게 할당된 승인 요청만 조회·처리한다(ADMIN은 전체, FR-LEAVE-002·003).
- 承認 탭 표시 판정(사이드바 休暇管理 하위 메뉴의 承認): ADMIN은 항상 표시. 그 외는 본인에게 할당된 신청(`PENDING`·`APPROVED`·`REJECTED`)이 1건 이상일 때만 표시한다(`GET /leaves/pending-approval?scope=mine&status=PENDING,APPROVED,REJECTED&limit=1`의 `totalCount > 0`, 조회 실패 시 숨김). `/leaves/approvals`에 직접 접근하면 판정 전에는 본문 대신 스켈레톤을 표시하고, 표시 대상이 아니면 `/leaves`로 replace한다(토스트 없음).
- 화면 접근 권한과 데이터 조회 권한은 서버에서도 검증한다(NFR-001).

## Common UI Rules

모든 화면에 공통으로 적용한다. 각 화면명세에는 화면 고유의 문구와 예외만 적는다.

### 인증 및 권한 처리

| 상황 | 처리 |
|---|---|
| 미인증 사용자가 보호된 화면에 접근 | `/login?redirect={원래 URL}`로 이동 |
| API 401(토큰 만료) | Refresh Token으로 1회 갱신 후 재시도. 실패하면 `/login?redirect=...`로 이동 |
| `mustChangePassword = true` 사용자 | `/password` 외 모든 화면 접근 시 `/password`로 이동 |
| 비관리자가 `/admin/*`에 접근 (페이지 진입 시 권한 없음) | `/dashboard`로 이동하고 "접근 권한이 없습니다." 토스트 표시 |
| API 403 `PASSWORD_CHANGE_REQUIRED` | `/password`로 이동 |
| API 403 `FORBIDDEN` (화면 안의 동작·모달) | 화면에 머무르고 토스트 표시, 필요 시 목록 다시 조회. 모달에서 발생하면 모달을 닫고 토스트 표시 |
| API 404 `NOT_FOUND` (모달 안 상세) | 모달을 닫고 목록 다시 조회 후 토스트 표시 |
| 앱 최초 로드 (새로고침 포함) | `POST /auth/refresh`로 Access Token 발급 → `GET /auth/me`로 사용자 정보 조회 → 이후 위 규칙 적용. 실패 시 `/login?redirect=...` |

### 상태 처리

| 상태 | 처리 |
|---|---|
| Loading | 목록·카드 영역에 스켈레톤 표시. 버튼 요청 중에는 버튼 비활성화와 스피너 표시 |
| Empty | 영역 안에 안내 문구 표시(문구는 화면별로 정의) |
| Error (조회 실패) | 영역 안에 "데이터를 불러오지 못했습니다." 문구와 [다시 시도] 버튼 |
| Error (처리 실패) | 서버 응답 `message`를 토스트로 표시. 입력 폼의 필드 오류는 해당 필드 아래 표시 |
| 네트워크 오류 | "네트워크 연결을 확인해주세요." 토스트 |
| 중복 제출 | 요청이 끝날 때까지 제출 버튼 비활성화 |

### 목록

- 페이지당 20건, 이전/다음 및 페이지 번호 이동
- 검색 조건을 바꾸면 1페이지로 이동
- 검색 조건과 페이지는 URL Query에 유지하여 뒤로 가기·새로고침 시 복원한다.
- 검색 버튼 문구: 기간 조회는 「照会」(SCR-003 md 미만·SCR-008), 키워드 조건 검색은 「検索」(SCR-006·010)를 쓴다.

### 모달

- 휴가 상세는 모든 화면에서 같은 "휴가 상세 모달"을 사용한다(SCR-004 4.4 참조).
- 휴가 신청은 SCR-004의 "공통 휴가 신청 모달"에서만 한다(SCR-004 3.2 참조. SCR-002의 신청 진입은 2026-11 삭제).
- 확인이 필요한 처리(출근, 퇴근, 취소, 승인, 반려, 비활성화)는 확인 모달을 거친다.

### 전역 내비게이션

로그인 후 모든 화면의 좌측 사이드바에 메뉴(아이콘 포함)를 표시하고, 상단바에는 알림 벨과 사용자 메뉴를 표시한다(09_DESIGN_SYSTEM §3 App Shell 참조).

| 메뉴 | URL | 표시 대상 |
|---|---|---|
| 대시보드 | /dashboard | 공통 |
| 출근부(`出勤簿`) | /attendance | 공통 |
| 휴가 관리 | (하위 메뉴) /leaves(自分の休暇)·/leaves/calendar(休暇カレンダー)·/leaves/approvals(承認) | 공통 (承認은 표시 대상만, 아래 承認 탭 표시 판정과 같음. 배지: 본인에게 할당된 승인 대기 건수, `GET /leaves/pending-approval?scope=mine&limit=1`의 `totalCount`. ADMIN도 동일 기준. 배지는 부모 행에 표시) |
| 사원 관리 | /admin/users | 관리자 |
| 부서 관리 | /admin/departments | 관리자 |
| 전체 근태 | /admin/attendance | 관리자 |
| 사용자 메뉴: 이름, 비밀번호 변경(/password), 로그아웃 | - | 공통 |

- 승인 대기 배지: 셸 표시 시, 화면 이동 시, 승인·반려 성공 후(SCR-005·대시보드) 다시 조회한다. 0건이면 숨기고, 100건 이상은 "99+"로 표시한다. 조회 실패 시 배지를 숨기며 토스트는 표시하지 않는다.
- 알림 벨: 알림 기능은 없다. 벨은 `/leaves/approvals` 링크이며, 승인 대기 배지와 같은 건수가 1건 이상이면 빨간 점을 표시한다(건수 숫자는 표시하지 않음).
- 휴가 관리 하위 메뉴(2026-11, SCR-004 페이지 안 탭 대체): 부모 행 「休暇管理」는 링크가 아니라 개폐 버튼이며, 누르면 아래로 自分の休暇·休暇カレンダー·承認(표시 대상만)이 펼쳐진다. `/leaves`·`/leaves/*`에 들어오면(직접 접근·뒤로/앞으로·다른 메뉴에서 이동) 자동으로 펼친다. 펼친 상태에서 사용자가 접으면 화면을 옮길 때까지 유지한다. 현재 화면의 하위 항목이 활성이며, 접힌 상태로 하위 화면에 있으면 부모 행이 활성 표시가 된다. 좁은 폭 드로어도 같은 메뉴다.
- 사이드바의 별도 「休暇承認」 메뉴는 SCR-005의 SCR-004 통합(2026-11)으로 삭제했다. 승인 화면은 휴가 관리의 承認 하위 메뉴로 들어간다. 社員情報·各種設定 메뉴는 해당 화면이 없어 추가하지 않는다(사용자 결정).
- 좁은 폭(`lg` 미만): 사이드바를 숨기고 화면 하단에 탭을 고정 표시한다. 탭은 ホーム(/dashboard)·出勤簿(/attendance)·休暇管理(/leaves 링크(하위 메뉴 없음), `/leaves/*` 포함 활성, 승인 대기 1건 이상이면 빨간 점)·メニュー 4개이며 모든 사용자에게 같다. 「メニュー」는 사이드바와 같은 메뉴(관리자 메뉴 포함)를 담은 드로어를 연다. 드로어는 배경 클릭, Esc, 메뉴 선택 시 닫힌다. 상단바에 햄버거 버튼은 없다.
- 로그아웃: `POST /auth/logout` 호출 후 `/login`으로 이동한다(API 실패 시에도 로컬 인증 정보를 지우고 이동).
- `mustChangePassword = true`인 사용자: 상단바에 로그아웃만 표시하고 사이드바 메뉴는 숨긴다(SCR-009).

### 공휴일 취급

- SCR-003(출근부)만 일본 공휴일을 휴일로 취급한다(API-ATT-007의 `dayType`·`holidayName` 기준, 화면에서 판정하지 않음).
- SCR-002 대시보드의 출근 집계(전사·부서별)도 출근부와 같은 기준으로 토·일·일본 공휴일을 비근무일로 취급한다(서버 응답 `isWorkday`).
- SCR-004 휴가 일수는 공휴일을 평일로 취급한다(FR-LEAVE-001). 화면 간 통일은 후속 과제이다(FR-ATT-006).

### 표시 언어

- 화면에 표시되는 모든 문구(라벨, 버튼, 토스트, 오류 메시지)는 **일본어**로 표시한다.
- 이 문서와 각 화면명세의 한국어 문구는 의미를 나타내는 기준이며, 실제 일본어 문구는 구현 시 표시 문자열 사전 한 곳에서 관리한다.

## Screen Flow

```
/login ──(성공)──> mustChangePassword ? /password : (redirect 또는 /dashboard)
/password ──(변경 완료)──> /dashboard
사이드바 休暇管理 ──[하위 메뉴]──> /leaves(自分の休暇) | /leaves/calendar(休暇カレンダー) | /leaves/approvals(承認, 표시 대상만)
/leaves/* ──[休暇申請]──> 공통 휴가 신청 모달 (세 탭 공통 헤더. 대시보드에는 신청 버튼 없음)
/leaves/calendar ──[막대·+N件]──> 휴가자 모달(PC) / ──[날짜 셀]──> 선택일 휴가자 목록(모바일)
/dashboard ──[승인 대기 すべて見る]──> /leaves/approvals (ADMIN은 ?scope=all)
/dashboard ──[승인 대기 항목]──> 휴가 상세 모달(승인·반려, 승인자·ADMIN)
/dashboard ──[최근 신청 항목]──> 휴가 상세 모달(취소)
/leaves ──[상세]──> 휴가 상세 모달(취소)
/leaves/approvals ──[상세]──> 휴가 상세 모달
/admin/users ──[상세보기]──> /admin/users/:id ──[목록으로]──> /admin/users(검색 조건 유지)
/admin/attendance ──[사원명]──> /admin/users/:id
```
