# SCR-006: 사원 관리(社員管理)

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-006 |
| 화면명 | 사원 관리(社員管理) |
| URL | /admin/users |
| 접근 권한 | 관리자 |
| 관련 요구사항 | FR-USER-001, FR-USER-002, FR-JOB-001 |

2026-11 레퍼런스 화상 기준으로 재작성했다. 이전 명세의 상세 검색(이름·사원번호·권한·승인 필요·입사일 기간)과 SCR-007 페이지 이동은 화면에서 쓰지 않는다(API-USER-001은 기존 Query도 그대로 지원). 사원 상세·수정은 이 화면의 모달로 대체했다(SCR-007 참조).

## 2. 화면 목적

관리자가 사원을 조회·검색하고, 같은 화면의 모달에서 등록·상세 확인·수정·삭제(비활성화)와 직책(役職) 관리를 한다.

- 이 화면은 「社員ID」 표기를 쓴다(로그인 등 다른 화면은 「社員番号」 유지). 값은 사원번호(`empId`)와 같다.
- 외형은 레퍼런스를 우선한다. 원형 아이콘 모달·라벨 위 스택 폼·boxed 페이지네이션·원형 아이콘 받침 StatCard는 이 화면 한정 예외다(09 §5 12, `docs/UI_MODAL_PATTERNS.md` 예외 E1).

## 3. 화면 구성

### 3.1 헤더

- `PageHeader`: 제목 「社員管理」, 설명 「社員情報の確認・追加・編集・削除を行います。」
- 버튼: [役職確認](`primaryOutline`, 役職確認 모달) / [社員追加](`primary`, 社員追加 모달). 좁은 폭에서는 제목 아래 줄로 내려간다.

### 3.2 요약(StatCard 3개, API-USER-006)

| 라벨 | 값 | 기준 |
|---|---|---|
| 社員数 | `employeeCount` 名 | 활성 사원(入社予定 포함) |
| 管理者数 | `adminCount` 名 | 활성이고 권한 `ADMIN`(役職 아님) |
| 今月の入社 | `hiredThisMonthCount` 名 | 활성이고 입사일이 Asia/Tokyo 이번 달 |

- 검색 조건과 무관하다. 로딩 스켈레톤, 실패 시 값 「—」 + 요약 아래 SectionError(再試行).
- 주의: 「社員数」(활성 기준)와 목록 제목 「社員一覧（全 N 名）」(현재 검색 조건 결과, 기본 ステータス 「すべて」이므로 無効 포함)는 기준이 달라 값이 다를 수 있다(의도된 동작).

### 3.3 검색 조건

| 요소 | 타입 | 설명 |
|---|---|---|
| 社員検索 | SearchInput | placeholder 「社員ID・氏名・メールアドレスで検索」. 사원번호·이름·메일 중 하나라도 부분 일치(대소문자 무시). 300ms 디바운스 |
| 所属部署 | Select | すべて / 부서 목록(API-DEPT-001) |
| 役職 | Select | すべて / 직책 목록(API-JOB-001) |
| ステータス | Select | すべて(기본) / 在籍中 / 入社予定 / 無効 |
| クリア | Button(`secondary`) | 모든 조건 초기화. 조건이 없으면 비활성 |

- 조건 변경 시 1페이지로 이동. 조건·페이지는 URL Query(`keyword`·`departmentId`·`jobTitleId`·`status`·`page`)에 유지하고 기본값은 생략한다. 잘못된 `status`는 「すべて」로 본다.
- 배치: xl(1280px) 이상 1행, 미만은 검색창이 별도 행.
- 재직 상태 정의는 FR-USER-001(在籍中 = 활성·입사일 ≤ 오늘, 入社予定 = 활성·입사일 > 오늘, 無効 = 비활성). 「休職中」은 없다.

### 3.4 목록(Card 「社員一覧（全 {totalCount} 名）」)

입사일 오름차순, 같은 날이면 사원번호 오름차순. **페이지당 10건**(03 공통 규칙 20건의 예외).

| 컬럼 | 설명 |
|---|---|
| 社員ID | 사원번호 |
| 氏名 | 이름 |
| 役職 | `JobTitleBadge`(직책 tone 색 pill), 미설정 「—」 |
| メールアドレス | 連絡先, 미설정 「—」 |
| 所属部署 | 부서명 |
| 入社日 | `YYYY/MM/DD` |
| ステータス | 在籍中(`positive`)·入社予定(`info`)·無効(`neutral`) pill 배지 |
| 操作 | [詳細](aria 「{name}の詳細」) [編集](aria 「{name}を編集」) [削除](icon only, aria 「{name}を削除」). 無効 행은 [削除] 숨김 |

- xl(1280px) 이상은 표, 미만은 카드 목록(가로 스크롤 없음).
- 하단 `Pagination`(boxed): 「全 {total} 件中 {from} – {to} 件を表示」, sm 미만 compact.
- Empty: 「条件に一致する社員はいません。」, 실패: SectionError(再試行).
- 등록·수정·삭제·직책 변경 성공 시 목록·요약(직책 변경 시 직책 목록 포함)을 다시 조회한다(전체 리로드 없음).

## 4. 모달

모든 모달은 원형 아이콘(`iconVariant="circle"`)을 쓴다(이 화면 한정 예외, UI_MODAL_PATTERNS 예외 E1).

### 4.1 役職確認(`Modal` lg, 단계형 list / form / confirmDelete)

- 설명 「役職の確認・追加・編集・削除を行います。」
- list: 「登録されている役職（{n}件）」, 표(役職名 = `JobTitleBadge`, 操作 = [{name}を編集]·[{name}を削除]), 아래 [追加]. 0건 「登録されている役職はありません。」. footer [閉じる]
- form(추가·편집): 「役職名」*(50자), 색 선택 패널 「色を選択」(설명 「役職の追加・編集時に、役職の色を選択できます。」, radiogroup 「色」 8색: 紫·青·グレー·薄紫·緑·黄·オレンジ·ピンク, 화살표 키 이동), 「プレビュー」(입력 이름·선택 색 실시간). Notice 「選択した色は、システム内でその役職が表示されるすべての箇所でカプセルバッジの色として使用されます。」. footer [キャンセル](list로) [保存]
  - [保存]은 form 단계에서만 표시한다. 각 조작(추가·편집·삭제)은 항목마다 즉시 API에 반영된다(일괄 저장 없음).
  - 성공 토스트 「役職を追加しました。」/「役職を更新しました。」
- confirmDelete: 「「{name}」を削除しますか？」, [キャンセル] [削除]. 성공 토스트 「役職を削除しました。」
- 직책은 인증 권한과 별개이며 변경해도 사원의 권한은 바뀌지 않는다. 색 변경은 이 화면 목록과 SCR-010 所属社員確認의 배지에 바로 반영된다.

### 4.2 社員追加(`FormModal` lg, `FormStack` 라벨 위 배치)

- 설명 「新しい社員情報を登録します。」

| 항목 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 社員ID | 라디오 카드 「自動生成」(기본)/「直接入力」 | O | 自動生成: 예정 번호(API-USER-007)를 읽기 전용 텍스트로 표시(입력란 아님). 로딩 「取得中…」, 조회 실패 「—」(등록 가능), `empId: null`이면 「自動生成できません。直接入力してください。」. 힌트 「社員IDは自動で連番（5桁の数字）で生成されます。登録時に確定します。」 / 直接入力: 숫자 1~50자리 |
| 社員名 | Input | O | 최대 100자, 제어 문자 불가 |
| 役職 | Select | O | 직책 목록. 선택하면 옆에 배지 미리보기 |
| メールアドレス | Input(email) | O | 형식·254자 이하 |
| 所属部署 | Select | O | 부서 목록(未所属 포함) |
| 入社日 | Date | O | 기본값 없음, 미래 허용(레퍼런스에 없는 추가 항목) |
| 初期パスワード | Password Input | O | FR-AUTH-003 규칙. 힌트 「8文字以上で、英字と数字を含めてください。社員は初回ログイン時に変更します。」(레퍼런스에 없는 추가 항목) |

- 하단 Notice 「追加後、社員情報は一覧の「編集」から変更できます。」
- 권한 `EMPLOYEE`·승인 필요 `true`를 고정 전송한다(화면에 표시하지 않음. 변경은 社員編集).
- footer [キャンセル] [追加する]. 제출 중 닫기·재제출 불가. 검증 실패 시 첫 오류 필드로 포커스.
- 성공: 모달을 닫고 토스트 「社員（社員ID: {empId}）を登録しました。初回ログイン時にパスワードの変更が必要です。」(empId는 확정 번호). 메일 발송·비밀번호 재발급 기능은 없다.
- 열 때마다 입력 상태(비밀번호 포함)를 초기화한다.

### 4.3 社員詳細(`Modal` lg, `DetailTable`)

- 항목: 社員ID, 氏名, 役職(배지), メールアドレス, 所属部署, 入社日, ステータス(배지), 権限(管理者/一般), 休暇承認(必要/不要), パスワード変更(必要/済み), 登録日, 更新日. 부여 연차는 표시하지 않는다.
- footer [閉じる] [編集](社員編集으로 전환). 404는 모달을 닫고 「社員が見つかりません。」 토스트 + 목록 재조회.

### 4.4 社員編集(`Modal` lg, `FormStack`, 단계형 form / confirm)

- 설명 「社員情報を変更します。」, 초기값은 API-USER-003.
- 항목: 社員ID*(직접 입력), 社員名*, 役職(「未設定」 허용), メールアドレス(빈 값 = 해제), 所属部署*, 入社日*, 権限*(管理者/一般), 休暇承認*(必要/不要), アカウント状態*(有効/無効). 비밀번호는 바꿀 수 없다.
- 변경한 필드만 PATCH. 변경이 없으면 [保存] 비활성.
- 有効 → 無効으로 저장하면 같은 모달에서 확인 단계: 「この社員を無効にしますか？無効にすると、この社員はログインできなくなり、申請中の休暇は取り消されます。」 → [無効にする](`danger`).
- 성공 토스트 「保存しました。」. 409 LAST_ADMIN은 폼 위 Notice(error)에 서버 message, 입력값 유지.

### 4.5 社員削除(`ConfirmDialog` tone danger)

- 「削除」 = 비활성화(PATCH `{isActive:false}`). 물리 삭제하지 않는다.
- 제목 「社員を削除」, 본문 「「{name}」を削除しますか？削除すると、この社員はログインできなくなり、申請中の休暇は取り消されます。社員データは「無効」として残ります。」
- 이 사원에게 할당된 승인 대기가 있으면 경고 「この社員に割り当てられた承認待ち {n} 件は、管理者が代理で処理してください。」
- 성공 토스트 「社員を削除しました。」. 409 LAST_ADMIN은 토스트(서버 message).

## 7. 권한 및 예외

- ADMIN만 접근할 수 있으며 서버에서도 검증한다.

| 응답 | 처리 |
|---|---|
| 400 VALIDATION_ERROR(details) | 해당 필드 아래 서버 message |
| 409 DUPLICATE_EMP_ID | 社員ID 필드 아래 「この社員IDは既に使用されています。」 |
| 409 EMP_ID_EXHAUSTED | 社員ID 필드 아래 서버 message(直接入力 권장) |
| 400 INVALID_DEPARTMENT / INVALID_JOB_TITLE | 해당 목록 재조회 + 필드 오류 |
| 409 LAST_ADMIN | 編集: 폼 위 Notice(error), 削除: 토스트 |
| 404 NOT_FOUND(社員) | 모달을 닫고 목록 재조회 + 「社員が見つかりません。」 |
| 409 DUPLICATE_JOB_TITLE_NAME | 役職名 필드 아래 「この役職名は既に登録されています。」 |
| 409 JOB_TITLE_IN_USE | 삭제 확인 단계 유지, Notice(error) 「この役職を使用している社員が存在するため、削除できません。」, [削除] 비활성 |
| 404 NOT_FOUND(役職) | 직책 목록 재조회 + 「役職が見つかりません。」 |
| 그 외 | 폼 위 Notice(error) 또는 토스트(03 공통 규칙) |

## 8. 반응형

- 1440·1024·390·375에서 가로 overflow 없음. 모달은 본문만 스크롤하고 footer 고정.
- 표는 xl(1280px) 이상만(lg는 사이드바 때문에 8열이 들어가지 않음), 미만은 카드.
- 375에서 StatCard 아이콘 받침은 32px로 줄인다.

## 9. 완료 조건

- 요약·목록 조회와 키워드·부서·役職·상태 검색이 가능하고 조건이 URL에 유지된다.
- 자동 채번/직접 입력과 관리자가 입력한 초기 비밀번호로 사원을 등록할 수 있고, 등록 사원은 최초 로그인 시 비밀번호 변경이 필요하다.
- 모달에서 상세 확인·수정·삭제(비활성화)가 가능하고 마지막 활성 ADMIN은 보호된다.
- 직책을 추가·편집(색 8색)·삭제할 수 있고 색이 모든 배지에 반영된다. 사용 중 직책은 삭제할 수 없다.
- 관리자가 아닌 사용자의 접근이 차단된다.
