# SCR-001: 로그인

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-001 |
| 화면명 | 로그인 |
| URL | /login |
| 접근 권한 | 비로그인 |
| 관련 요구사항 | FR-AUTH-001, FR-AUTH-002 |

## 2. 화면 목적

등록된 사용자가 사원번호와 비밀번호를 입력하여 시스템에 로그인한다.

## 3. 화면 구성

| ID | 요소 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| E-001 | 사원번호 | Input | O | 로그인 ID |
| E-002 | 비밀번호 | Password Input | O | 로그인 비밀번호 |
| E-003 | 로그인 버튼 | Button | - | 로그인 실행. Enter 키로도 실행 |

- 좁은 폭 배치: 가운데 정렬 카드(최대 폭 540px)는 폭이 줄면 좌우 여백 16px을 남기고 전체 폭으로 늘어나며(360px에서도 가로 스크롤 없음), 카드 내부 여백만 40px에서 28px로 줄인다.

## 4. 동작 명세

### 로그인

1. 사원번호와 비밀번호를 입력한다.
2. 로그인 버튼을 클릭한다.
3. 입력값을 검증한다.
4. 로그인 API를 호출한다(요청 중 버튼 비활성화).
5. 인증 성공 시 Access Token과 사용자 정보를 저장한다(Refresh Token은 httpOnly 쿠키).
6. 이동
   - `mustChangePassword = true`이면 `/password`로 이동한다.
   - 그렇지 않으면 `redirect` Query가 있으면 해당 URL로, 없으면 `/dashboard`로 이동한다.
   - `redirect`는 서비스 내부 경로(`/`로 시작)만 허용한다.

### 이미 로그인된 사용자

- 로그인 상태에서 `/login`에 접근하면 `/dashboard`로 이동한다.

## 5. 유효성 검증

| 대상 | 조건 | 메시지 |
|---|---|---|
| 사원번호 | 필수 입력 | 사원번호를 입력해주세요. |
| 비밀번호 | 필수 입력 | 비밀번호를 입력해주세요. |

## 6. API

- `POST /api/v1/auth/login` (API-AUTH-001)
  - Request: `empId`, `password`
  - Response: `accessToken`, `user`(id, name, empId, role, departmentName, approvalRequired, mustChangePassword)

## 7. 예외 처리

| 상황 | 응답 | 처리 |
|---|---|---|
| 인증 실패 | 401 INVALID_CREDENTIALS | 사원번호 또는 비밀번호가 올바르지 않습니다. |
| 비활성 계정 | 403 ACCOUNT_DISABLED (비밀번호가 맞은 경우에만 반환됨) | 사용할 수 없는 계정입니다. 관리자에게 문의해주세요. |
| 네트워크 오류 | - | 네트워크 연결을 확인해주세요. |
| 서버 오류 | 500 | 로그인 처리 중 오류가 발생했습니다. |

오류 메시지는 폼 상단에 표시하고, 비밀번호 입력값을 비운다.

## 8. 완료 조건

- 정상적인 계정으로 로그인할 수 있다.
- 잘못된 로그인 정보나 비활성 계정으로는 로그인할 수 없다.
- 인증 성공 후 redirect 대상 또는 대시보드로 이동한다.
- 비밀번호 변경이 필요한 사용자는 비밀번호 변경 화면으로 이동한다.
- 미인증 사용자의 보호된 API 접근이 차단된다.
