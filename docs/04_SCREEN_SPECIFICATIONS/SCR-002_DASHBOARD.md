# SCR-002: 대시보드

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-002 |
| 화면명 | 대시보드 |
| URL | /dashboard |
| 접근 권한 | 공통 |
| 관련 요구사항 | FR-DASH-001, FR-ATT-001, FR-ATT-002, FR-LEAVE-001, FR-LEAVE-002, FR-LEAVE-003, FR-LEAVE-006 |

## 2. 화면 목적

로그인한 사용자의 당일 근태 상태, 휴가 현황, 본인에게 할당된 승인 대기 현황을 한눈에 확인한다.
ADMIN은 오늘의 전체 현황도 함께 확인한다.
모든 사용자는 월간 휴가 캘린더에서 날짜별로 누가 승인된 휴가로 부재인지 확인한다.

## 3. 화면 구성

사이드바(메뉴)와 상단바(사용자 이름, 비밀번호 변경, 로그아웃)는 03 Common UI Rules의 전역 내비게이션을 따른다.

좁은 폭 배치(09 §5-3):
- 오늘 전체 현황 stats 카드는 기본 2열, `xl` 이상 4열로 표시한다.
- 승인 대기 현황은 `md` 이상에서 표, `md` 미만에서 목록으로 표시한다.
- 휴가 캘린더는 날짜 칸 높이를 `md` 이상 96px, `md` 미만 56px로 한다. `md` 미만에서는 날짜 숫자를 12px로 줄이고, 인원 표시는 칸의 좌우 여백 없이 칸 폭 전체를 채우는 띠(12px)로 표시한다. 카드 헤더의 월 이동 컨트롤은 제목과 한 줄에 들어가지 않으면 다음 줄로 내려간다(제목은 줄이지 않고 한 줄 유지, 09 §6 Card). 날짜 상세 모달의 목록은 폭과 관계없이 표(社員番号·社員名·所属部署)로 표시한다.

### 3-1. 상단 영역

- 사용자 이름, 소속 부서
- 현재 날짜

### 3-2. 오늘 전체 현황 (ADMIN만 표시)

| 요소 | 설명 |
|---|---|
| 출근 인원 | 오늘 출근 등록한 활성 사용자 수 |
| 미출근 인원 | 오늘 출근 기록이 없고 휴가 중이 아닌 활성 사용자 수 |
| 휴가 인원 | 오늘 APPROVED 휴가 중인 활성 사용자 수. 반차 포함(FR-DASH-001) |
| 승인 대기 | 전체 PENDING 건수. 클릭 시 `/leaves/approvals?scope=all`로 이동 |

### 3-3. 근태 현황

| 요소 | 설명 |
|---|---|
| 현재 근무 상태 | 미출근 / 근무 중 / 퇴근 완료 |
| 출근 시간 | 당일 출근 시간 |
| 퇴근 시간 | 당일 퇴근 시간 |
| 출근 버튼 | 미출근 상태에서만 활성화 |
| 퇴근 버튼 | 근무 중 상태에서만 활성화 |

### 3-4. 휴가 현황 (올해 기준)

| 요소 | 설명 |
|---|---|
| 부여 연차 | 올해 부여 일수 |
| 승인 완료 | 차감 대상 APPROVED 휴가 일수 |
| 승인 대기 | 차감 대상 PENDING 휴가 일수 |
| 잔여 연차 | 서버에서 계산한 값(FR-LEAVE-001) |
| 휴가 신청 버튼 | 공통 휴가 신청 모달(SCR-004 3.2)을 연다. 성공 시 모달을 닫고 휴가 현황을 다시 조회한다(화면 이동 없음) |

### 3-5. 승인 대기 현황

본인에게 할당된 PENDING 건을 최대 5건, 신청일 내림차순으로 표시한다.

| 컬럼 | 설명 |
|---|---|
| 신청자 | 신청자 이름 |
| 부서 | 소속 부서 |
| 휴가 종류 | 신청 휴가 종류 |
| 기간 | 시작일 ~ 종료일 |
| 일수 | 신청 일수 |
| 신청일 | 신청 등록일 |

- [전체보기] 링크: `/leaves/approvals`로 이동

### 3-6. 휴가 캘린더 (공통)

승인 대기 현황 아래에 컨테이너 전체 폭으로 표시한다. ADMIN·EMPLOYEE 모두 같은 내용이다(FR-DASH-001).

| 요소 | 설명 |
|---|---|
| 카드 제목 | 「休暇カレンダー」 |
| 월 이동 | 카드 헤더 오른쪽. [前月](‹) 「2026年11月」 [翌月](›). 아이콘 버튼이며 `aria-label`은 「前月」「翌月」. 초기값은 Asia/Tokyo 기준 이번 달 |
| 달력 | 일요일 시작(日 月 火 水 木 金 土) 월간 표. 시스템 컴포넌트 `MonthCalendar`(09 §6) 사용. 해당 월이 아닌 앞뒤 칸은 빈 칸 |
| 오늘 | 날짜 숫자 원형 강조 + 칸 테두리, `aria-current="date"` |
| 과거 날짜 | 배경·숫자를 흐리게 표시하되 클릭할 수 있다 |
| 인원 배지 | 그 날짜의 `APPROVED` 휴가 인원이 1명 이상이면 「{n}名」 배지. 0명이면 표시하지 않는다. 토·일은 집계하지 않으므로 표시되지 않는다 |
| 날짜 상세 모달 | 날짜 칸 클릭 시 표시. 제목 「{YYYY年MM月DD日}の休暇」(예: 2026年11月05日の休暇). 목록은 헤더 「社員番号」「社員名」「所属部署」가 있는 표이며, 반차일 때만 社員名 뒤에 「午前半休」「午後半休」 라벨. 표 오른쪽 아래에 그날 총 휴가 인원 「合計 {n}名」. 하단 [閉じる] |

- 표시하지 않는 항목: 신청 사유, 반차 외 휴가 종류, 기간, 상태 배지, 승인 대기(`PENDING`) 건. API 응답에도 포함되지 않는다(FR-DASH-001).
- 원 요청과 달라진 점: 원 요청(8-3)은 목록에 신청 사유와 휴가 상태를 함께 표시하도록 했으나, 사용자 결정으로 사유는 ADMIN을 포함해 표시하지 않고, `APPROVED`만 다루므로 상태도 표시하지 않는다. 반차는 상태 대신 「午前半休」「午後半休」 라벨로만 구분한다.
- 같은 사용자가 같은 날 午前半休와 午後半休를 모두 가지거나 종일 휴가와 반차가 겹치면 라벨 없이 1행으로 표시한다.

## 4. 동작 명세

### 출근

1. 출근 버튼 클릭
2. 확인 모달("출근을 등록하시겠습니까?")
3. 출근 API 호출
4. 성공 시 출근 시간과 근무 상태 갱신, 토스트 "출근이 등록되었습니다."

### 퇴근

1. 퇴근 버튼 클릭
2. 확인 모달("퇴근을 등록하시겠습니까?")
3. 퇴근 API 호출
4. 성공 시 퇴근 시간과 근무 상태 갱신, 토스트 "퇴근이 등록되었습니다."

### 승인 대기 처리

1. 승인 대기 항목을 클릭하면 휴가 상세 모달을 표시한다(SCR-004 4.4).
2. 모달에서 [승인] 또는 [반려]를 선택한다. 처리 흐름은 SCR-005 6·7과 같다.
3. 처리가 끝나면 승인 대기 현황과(ADMIN이면) 오늘 전체 현황을 다시 조회한다. 휴가 캘린더도 표시 중인 월을 유지한 채 다시 조회한다.

### 휴가 캘린더

1. 처음 표시할 때 이번 달(Asia/Tokyo)의 날짜별 인원을 조회한다(API-DASH-002).
2. [前月] / [翌月]을 누르면 표시 월을 바꾸고 그 월의 인원만 다시 조회한다.
3. 날짜 칸(과거 포함)을 누르면 날짜 상세 모달을 열고 그 날짜 1일분의 휴가자 목록을 조회한다(API-DASH-003). 월 인원은 다시 조회하지 않는다. 모달을 열 때마다 새로 조회한다.
4. 휴가 현황의 휴가 신청이 성공하면(즉시 승인 사용자 반영) 표시 중인 월을 다시 조회한다.

## 5. 권한별 표시

| 요소 | EMPLOYEE | ADMIN |
|---|---|---|
| 오늘 전체 현황 | X | O |
| 개인 근태 | O | O |
| 개인 휴가 현황 | O | O |
| 승인 대기 현황 (본인 할당) | O | O |
| 휴가 캘린더 | O | O |

승인 대기 현황은 모든 사용자에게 표시하며, 할당된 건이 없으면 Empty 상태로 표시한다.
휴가 캘린더는 ADMIN·EMPLOYEE에게 같은 내용(사원번호·이름·소속 부서·반차 구분)을 표시하며, ADMIN에게도 신청 사유를 표시하지 않는다. 사유는 기존 휴가 상세 모달(API-LEAVE-004)에서 확인한다.

## 6. API

| 영역 | API |
|---|---|
| 오늘 전체 현황 | `GET /admin/dashboard/summary` (API-DASH-001) |
| 근태 현황 | `GET /attendance/today` (API-ATT-003) |
| 출근 / 퇴근 | `POST /attendance/clock-in` (API-ATT-001), `POST /attendance/clock-out` (API-ATT-002) |
| 휴가 현황 | `GET /leaves/balance` (API-LEAVE-006) |
| 승인 대기 | `GET /leaves/pending-approval?scope=mine&limit=5` (API-LEAVE-007) |
| 상세 / 승인 / 반려 | `GET /leaves/:id`, `PATCH /leaves/:id/approve`, `PATCH /leaves/:id/reject` (API-LEAVE-004, 008, 009) |
| 휴가 캘린더 (월 인원) | `GET /dashboard/leave-calendar?month=YYYY-MM` (API-DASH-002) |
| 휴가 캘린더 (날짜 상세) | `GET /dashboard/leave-calendar/day?date=YYYY-MM-DD` (API-DASH-003) |

각 영역은 독립적으로 조회하며, 한 영역이 실패해도 다른 영역은 표시한다.

## 7. 상태 처리

공통 규칙(03 Common UI Rules)을 따르며 화면 고유 사항은 다음과 같다.

| 상황 | 처리 |
|---|---|
| 승인 대기 Empty | 승인 대기 중인 요청이 없습니다. |
| 휴가 캘린더 월 조회 중 / 실패 | 달력 자리에 스켈레톤 / 영역 내 SectionError + [再試行] |
| 휴가 캘린더 인원 0명인 날 | 배지를 표시하지 않는다 |
| 날짜 상세 조회 중 / 실패 | 모달 안 스켈레톤 3줄 / 모달 안 SectionError + [再試行] |
| 날짜 상세 Empty | この日の休暇取得者はいません。 (토·일 포함) |
| 부여 연차 미등록 | 부여 연차 0일로 표시하고 "부여 연차가 등록되지 않았습니다." 안내. 판정은 `grantedDays === 0` |
| 409 ALREADY_CLOCKED_IN | 이미 출근이 등록되었습니다. (오늘 근태 다시 조회) |
| 409 NOT_CLOCKED_IN | 오늘 출근 기록이 없습니다. |
| 409 ALREADY_CLOCKED_OUT | 이미 퇴근이 등록되었습니다. |
| 409 ALREADY_PROCESSED (승인/반려) | 이미 처리된 요청입니다. 목록을 새로고침합니다. (목록 다시 조회, SCR-005와 같은 문구) |

## 8. 완료 조건

- 로그인한 사용자 본인의 근태와 휴가 데이터만 표시한다. 단, 휴가 캘린더는 예외로 모든 사용자에게 승인된 휴가자의 사원번호·이름·소속 부서·반차 구분을 표시한다(사유·종류·기간·상태는 표시하지 않음).
- 휴가 캘린더에 날짜별 `APPROVED` 휴가 인원이 표시되고, 월 이동과 날짜 선택 시 휴가자 목록 표시가 가능하다.
- 출근 및 퇴근 처리가 가능하다.
- 휴가 현황이 서버 계산값대로 표시된다.
- 본인에게 할당된 승인 대기만 표시되며, 상세 모달에서 승인 또는 반려할 수 있다.
- ADMIN에게만 오늘 전체 현황이 표시된다.
