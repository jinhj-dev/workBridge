# SCR-002: 대시보드

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-002 |
| 화면명 | 대시보드 |
| URL | /dashboard |
| 접근 권한 | 공통 |
| 관련 요구사항 | FR-DASH-001, FR-ATT-001, FR-ATT-002, FR-LEAVE-001, FR-LEAVE-002, FR-LEAVE-003, FR-LEAVE-006 |

## 2. 화면 목적

로그인한 사용자의 당일 근태 상태, 휴가 현황, 본인에게 할당된 승인 대기 현황을 한눈에 확인한다.
ADMIN은 오늘의 전체 현황도 함께 확인한다.

## 3. 화면 구성

사이드바(메뉴)와 상단바(사용자 이름, 비밀번호 변경, 로그아웃)는 03 Common UI Rules의 전역 내비게이션을 따른다.

좁은 폭 배치(09 §5-3):
- 오늘 전체 현황 stats 카드는 기본 2열, `xl` 이상 4열로 표시한다.
- 승인 대기 현황은 `md` 이상에서 표, `md` 미만에서 목록으로 표시한다.

### 3-1. 상단 영역

- 사용자 이름, 소속 부서
- 현재 날짜

### 3-2. 오늘 전체 현황 (ADMIN만 표시)

| 요소 | 설명 |
|---|---|
| 출근 인원 | 오늘 출근 등록한 활성 사용자 수 |
| 미출근 인원 | 오늘 출근 기록이 없고 휴가 중이 아닌 활성 사용자 수 |
| 휴가 인원 | 오늘 APPROVED 휴가 중인 활성 사용자 수. 반차 포함(FR-DASH-001) |
| 승인 대기 | 전체 PENDING 건수. 클릭 시 `/leaves/approvals?scope=all`로 이동 |

### 3-3. 근태 현황

| 요소 | 설명 |
|---|---|
| 현재 근무 상태 | 미출근 / 근무 중 / 퇴근 완료 |
| 출근 시간 | 당일 출근 시간 |
| 퇴근 시간 | 당일 퇴근 시간 |
| 출근 버튼 | 미출근 상태에서만 활성화 |
| 퇴근 버튼 | 근무 중 상태에서만 활성화 |

### 3-4. 휴가 현황 (올해 기준)

| 요소 | 설명 |
|---|---|
| 부여 연차 | 올해 부여 일수 |
| 승인 완료 | 차감 대상 APPROVED 휴가 일수 |
| 승인 대기 | 차감 대상 PENDING 휴가 일수 |
| 잔여 연차 | 서버에서 계산한 값(FR-LEAVE-001) |
| 휴가 신청 버튼 | 공통 휴가 신청 모달(SCR-004 3.2)을 연다. 성공 시 모달을 닫고 휴가 현황을 다시 조회한다(화면 이동 없음) |

### 3-5. 승인 대기 현황

본인에게 할당된 PENDING 건을 최대 5건, 신청일 내림차순으로 표시한다.

| 컬럼 | 설명 |
|---|---|
| 신청자 | 신청자 이름 |
| 부서 | 소속 부서 |
| 휴가 종류 | 신청 휴가 종류 |
| 기간 | 시작일 ~ 종료일 |
| 일수 | 신청 일수 |
| 신청일 | 신청 등록일 |

- [전체보기] 링크: `/leaves/approvals`로 이동

## 4. 동작 명세

### 출근

1. 출근 버튼 클릭
2. 확인 모달("출근을 등록하시겠습니까?")
3. 출근 API 호출
4. 성공 시 출근 시간과 근무 상태 갱신, 토스트 "출근이 등록되었습니다."

### 퇴근

1. 퇴근 버튼 클릭
2. 확인 모달("퇴근을 등록하시겠습니까?")
3. 퇴근 API 호출
4. 성공 시 퇴근 시간과 근무 상태 갱신, 토스트 "퇴근이 등록되었습니다."

### 승인 대기 처리

1. 승인 대기 항목을 클릭하면 휴가 상세 모달을 표시한다(SCR-004 4.4).
2. 모달에서 [승인] 또는 [반려]를 선택한다. 처리 흐름은 SCR-005 6·7과 같다.
3. 처리가 끝나면 승인 대기 현황과(ADMIN이면) 오늘 전체 현황을 다시 조회한다.

## 5. 권한별 표시

| 요소 | EMPLOYEE | ADMIN |
|---|---|---|
| 오늘 전체 현황 | X | O |
| 개인 근태 | O | O |
| 개인 휴가 현황 | O | O |
| 승인 대기 현황 (본인 할당) | O | O |

승인 대기 현황은 모든 사용자에게 표시하며, 할당된 건이 없으면 Empty 상태로 표시한다.

## 6. API

| 영역 | API |
|---|---|
| 오늘 전체 현황 | `GET /admin/dashboard/summary` (API-DASH-001) |
| 근태 현황 | `GET /attendance/today` (API-ATT-003) |
| 출근 / 퇴근 | `POST /attendance/clock-in` (API-ATT-001), `POST /attendance/clock-out` (API-ATT-002) |
| 휴가 현황 | `GET /leaves/balance` (API-LEAVE-006) |
| 승인 대기 | `GET /leaves/pending-approval?scope=mine&limit=5` (API-LEAVE-007) |
| 상세 / 승인 / 반려 | `GET /leaves/:id`, `PATCH /leaves/:id/approve`, `PATCH /leaves/:id/reject` (API-LEAVE-004, 008, 009) |

각 영역은 독립적으로 조회하며, 한 영역이 실패해도 다른 영역은 표시한다.

## 7. 상태 처리

공통 규칙(03 Common UI Rules)을 따르며 화면 고유 사항은 다음과 같다.

| 상황 | 처리 |
|---|---|
| 승인 대기 Empty | 승인 대기 중인 요청이 없습니다. |
| 부여 연차 미등록 | 부여 연차 0일로 표시하고 "부여 연차가 등록되지 않았습니다." 안내. 판정은 `grantedDays === 0` |
| 409 ALREADY_CLOCKED_IN | 이미 출근이 등록되었습니다. (오늘 근태 다시 조회) |
| 409 NOT_CLOCKED_IN | 오늘 출근 기록이 없습니다. |
| 409 ALREADY_CLOCKED_OUT | 이미 퇴근이 등록되었습니다. |
| 409 ALREADY_PROCESSED (승인/반려) | 이미 처리된 요청입니다. 목록을 새로고침합니다. (목록 다시 조회, SCR-005와 같은 문구) |

## 8. 완료 조건

- 로그인한 사용자 본인의 근태와 휴가 데이터만 표시한다.
- 출근 및 퇴근 처리가 가능하다.
- 휴가 현황이 서버 계산값대로 표시된다.
- 본인에게 할당된 승인 대기만 표시되며, 상세 모달에서 승인 또는 반려할 수 있다.
- ADMIN에게만 오늘 전체 현황이 표시된다.
