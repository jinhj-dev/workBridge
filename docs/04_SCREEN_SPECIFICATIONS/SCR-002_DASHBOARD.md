# SCR-002: 대시보드

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-002 |
| 화면명 | 대시보드 |
| URL | /dashboard |
| 접근 권한 | 공통 |
| 관련 요구사항 | FR-DASH-001, FR-ATT-001, FR-ATT-002, FR-ATT-006, FR-LEAVE-001, FR-LEAVE-002, FR-LEAVE-003, FR-LEAVE-005, FR-LEAVE-006 |

## 2. 화면 목적

로그인한 사용자의 당일 출근 상태와 근무 진행, 이번 달 근무 집계, 휴가 잔여, 최근 휴가 신청, 부서별 출근 현황을 한눈에 확인한다.
승인자(본인에게 할당된 승인 대기가 있는 사용자)와 ADMIN은 승인 대기 신청을 확인하고 휴가 상세 모달에서 바로 승인·반려한다.
ADMIN은 전사 통계와 전사 출근 현황도 함께 확인한다.

## 3. 화면 구성

사이드바(메뉴), 상단바(알림 벨, 사용자 메뉴: 비밀번호 변경·로그아웃), `lg` 미만 하단 탭은 03 Common UI Rules의 전역 내비게이션과 09 §3 App Shell을 따른다.
카드는 공용 `Card`(아이콘 제목, 09 §6)를 쓰며, 시각 스타일은 09 §5-6(SCR-002 참조 디자인 재현)을 따른다. 공지(お知らせ) 카드와 휴가 캘린더는 없다.

### 3-0. 배치

- 순서: 헤더 → (ADMIN) 통계 카드 3개 → 카드 행. 카드·행 간격 16.
- `xl`(1280px) 이상은 행 단위 그리드, 미만은 1열. PC·모바일은 같은 컴포넌트·같은 조회를 쓰고 CSS(`contents`·`order`)로만 배치를 바꾼다(화면 폭 판정으로 다른 컴포넌트를 마운트하지 않는다). 같은 행의 카드는 높이를 맞춘다.

| 사용자 | `xl` 이상 행 | `xl` 미만 1열 순서 |
|---|---|---|
| ADMIN | ① 今日の出勤状況 \| 承認待ちの申請 ② 全社の出勤状況 \| 今月の勤務状況 ③ 休暇の残り日数 \| 各部署の状況 \| 直近の申請履歴 | 통계 → 全社 → 承認待ち → 今日 → 今月 → 休暇 → 部署 → 直近 |
| EMPLOYEE | (승인자만) 承認待ちの申請(전폭) → ① 今日の出勤状況 \| (今月の勤務状況 위 / 休暇の残り日数 아래 세로 배치) ② 各部署の状況 \| 直近の申請履歴 | DOM 순서 그대로(承認待ち → 今日 → 今月 → 休暇 → 部署 → 直近) |

좁은 폭 배치(09 §5-3):
- 통계 카드는 폭과 관계없이 3열이다. `sm` 미만은 아이콘·글자를 줄이고 수치를 라벨 아래 전체 폭에 둔다(라벨은 2줄로 꺾일 수 있다).
- 承認待ちの申請은 `md` 이상에서 표, `md` 미만에서 목록으로 표시한다. 표가 카드 폭을 넘치면 표 안에서만 가로 스크롤한다.
- 各部署の状況 표는 넘치면 표 안에서만 가로 스크롤한다.
- 今月の勤務状況 4칸은 폭과 관계없이 한 줄 4칸이다(좁으면 글자를 줄인다).

### 3-2. 통계 카드 (ADMIN만 표시)

아이콘 `StatCard` 3개(09 §6). 데이터는 API-DASH-001이며 3-5 全社の出勤状況과 같은 응답을 공유한다(1회 조회).

| 카드 | 값 | 비고 |
|---|---|---|
| 全社員数 | `totalEmployeeCount`名 | |
| 本日の出勤者 | `clockedInCount`名 | |
| 承認待ちの申請 | `pendingLeaveCount`件 | 강조색(tone `danger`). 카드 전체가 `/leaves/approvals?scope=all` 링크 |

### 3-3. 承認待ちの申請

표시 대상: ADMIN(항상) / 승인자인 EMPLOYEE(사이드바 승인 대기 배지 건수 > 0일 때만). 그 외 사용자에게는 카드 자체를 렌더하지 않는다(5절).

| 요소 | 설명 |
|---|---|
| 제목 | 「承認待ちの申請（{totalCount}件）」 |
| [すべて見る] | ADMIN → `/leaves/approvals?scope=all`, EMPLOYEE → `/leaves/approvals` |
| 목록 | 최대 5건, 신청일 내림차순. ADMIN은 전체 PENDING, EMPLOYEE는 본인 할당 PENDING |
| `md` 이상 표 | 社員名(인물 아이콘 + 이름) / 部署 / 休暇種別(Badge `info`) / 期間 / 상세 열(chevron, 헤더 「詳細」은 화면에서 숨김) |
| `md` 미만 목록 | 인물 아이콘, 이름·부서, 휴가 종류 배지, 기간·일수, chevron. 이름·부서는 한 줄로 말줄임하고(전체는 상세 모달에서 확인), 배지·기간은 줄바꿈하지 않는다 |
| 행 클릭 | 휴가 상세 모달(SCR-004 4.4)을 연다. 키보드는 이름 버튼(표)·행 버튼(목록)으로 연다 |
| 0건 | 표 헤더를 유지하고 헤더 아래에 「承認待ちの申請はありません。」(데이터 행 3개분 높이). `md` 미만도 0건이면 표로 표시(詳細 열 숨김) |

### 3-4. 今日の出勤状況

| 요소 | 설명 |
|---|---|
| 상태 일러스트 | 원형 아이콘(노트북). 출근 후에는 체크 표시를 겹친다(장식, 읽기 대상 아님) |
| 상태 배지 | 未出勤(neutral) / 勤務中(positive, 점 표시) / 退勤済み(dark) |
| 出勤時刻 | 당일 출근 시각. 출근 전 「--:--」 |
| 退勤時刻 | 당일 실제 퇴근 시각(HH:mm). 퇴근 전(未出勤·勤務中) 「--:--」. 퇴근 직후 API-ATT-002 응답으로 즉시 반영 |
| 今日の勤務進捗 | 진행 막대 + 「約 {n}%」. n = (기준 시각 − 출근 시각) / 9시간, 0~100 클램프, 정수 내림. 기준 시각: 근무 중 = 현재 시각(근무 중일 때만 1분마다 갱신), 退勤済み = 퇴근 시각. 출근 전 0% |
| 출퇴근 버튼 | 다음 동작 1개만 표시: 未出勤 → [出勤する](Primary) / 勤務中 → [退勤する](흰색 아웃라인) / 退勤済み → [退勤済み](비활성) |

- 진행률은 화면 표시용 目安이며 근태 기록·잔업 계산(FR-ATT-006)에는 쓰지 않는다(FR-DASH-001).
- 이전의 退勤予定（目安）(출근 + 9시간, D10) 표시는 사용자 요청으로 폐기하고 실제 退勤時刻 표시로 바꿨다(2026-11).

### 3-5. 全社の出勤状況 (ADMIN만 표시)

| 요소 | 설명 |
|---|---|
| 도넛 차트 | 정적 SVG `DonutChart`(09 §5-4 예외). 가운데 「出勤率」 + `attendanceRate`(소수 1자리 %, null이면 「—」). 색: 出勤 `primary-100` / 未出勤 `general-50` / 休暇 `violet-100`, 트랙 `general-40` |
| 범례 | 出勤 / 未出勤 / 休暇 각각 「{n}名（{p}%）」. p = 해당 인원 / (出勤 + 未出勤 + 休暇), 소수 1자리, 분모 0이면 「—」 |
| 비근무일 안내 | `isWorkday === false`이면 「本日は休日のため、出勤者のみ集計しています。」 |

### 3-6. 今月の勤務状況

이번 달(Asia/Tokyo) 출근부 집계(API-ATT-007 `summary`)를 4칸으로 표시한다. [詳細を見る] → `/attendance`.

| 칸 | 값 |
|---|---|
| 勤務日数 | `actualWorkDays`日 |
| 総労働時間 | `actualWorkMinutes`(「96時間」, 분이 있으면 「96時間30分」) |
| 残業時間 | `overtimeMinutes`(같은 표기) |
| 休日出勤 | `holidayWorkMinutes`(시간 표기) |

- 수치는 숫자를 크게, 단위를 작게 표시한다.
- 참조 디자인과 달리 4칸(休日出勤 포함)을 ADMIN·EMPLOYEE·모든 폭에서 유지하고, 休日出勤은 일수가 아니라 시간으로 표시한다(사용자 결정).

### 3-7. 休暇の残り日数 (올해 기준)

| 요소 | 설명 |
|---|---|
| 残日数 | `remainingDays`(서버 계산값, FR-LEAVE-001) |
| 承認済み日数 | `approvedDays`(API-LEAVE-006 값 그대로, 화면에서 재계산하지 않음) |
| [休暇履歴を見る] | `/leaves`. EMPLOYEE만 표시(ADMIN은 참조 디자인에 맞춰 표시하지 않음) |

- 대시보드에는 [休暇を申請] 버튼이 없다. 휴가 신청은 휴가 관리 화면(SCR-004)에서만 한다(사용자 결정).

### 3-8. 各部署の状況

모든 로그인 사용자에게 같은 내용(부서별 숫자만, 사원 이름·ID 없음, FR-DASH-001)을 표시한다.

| 요소 | 설명 |
|---|---|
| 표 | 部署 / 在籍人数 / 出勤（率） / 休暇 / 未出勤. 인원은 「{n}名」, 出勤 옆에 출근율 「（{p}%）」(null이면 「—」). 숫자 열 오른쪽 정렬. 헤더와 숫자 셀은 줄바꿈하지 않는다(「出勤（率）」은 항상 1줄, 넘치면 표 안 가로 스크롤). 참조 디자인의 アラート 열은 두지 않는다(데이터 없음, 사용자 결정) |
| 정렬·대상 | 서버 응답 순서 그대로(부서 코드 오름차순, 「未所属」 마지막, 대상자 0명 부서 제외) |
| [すべて見る] | ADMIN만 → `/admin/attendance` |
| 비근무일 안내 | 3-5와 같은 문구 |

### 3-9. 直近の申請履歴

본인 휴가 신청 최근 3건(신청일 내림차순). [すべて見る] → `/leaves`.

| 요소 | 설명 |
|---|---|
| 구분선 | 목록(또는 빈 상태 문구) 위에 1px `general-40` 선. 행 사이 구분선과 같은 색 |
| 행 | 휴가 종류, 기간, 상태 배지(`LeaveStatusBadge` soft). `sm` 미만은 왼쪽 원형 아이콘·오른쪽 chevron 추가 |
| 행 클릭 | 행 전체가 클릭 영역(포인터 커서)이며 휴가 상세 모달(SCR-004 4.4)을 연다. 본인 취소 규칙은 기존 그대로 |

## 4. 동작 명세

### 출근 / 퇴근

1. 3-4의 출퇴근 버튼 클릭([出勤する] 또는 [退勤する])
2. 확인 모달(「出勤を登録しますか？」 / 「退勤を登録しますか？」)
3. 출근(API-ATT-001) 또는 퇴근(API-ATT-002) 호출. 요청 중에는 중복 전송하지 않는다
4. 성공 시 응답으로 출근 상태와 出勤時刻·退勤時刻을 즉시 갱신하고 토스트(「出勤を登録しました。」 / 「退勤を登録しました。」). (ADMIN) 통계·全社, 各部署, 今月の勤務状況을 다시 조회한다
5. 409(7절)이면 오류 토스트 후 오늘 근태를 다시 조회한다

### 승인 대기 처리

1. 3-3의 항목을 클릭하면 휴가 상세 모달을 표시한다(SCR-004 4.4).
2. 모달의 [承認]·[却下] 노출과 처리 흐름은 SCR-005 6·7과 같다(처리 가능 여부와 권한은 서버가 판정).
3. 처리가 끝나면 승인 대기 목록, 사이드바 승인 대기 배지, (ADMIN) 통계·全社, 各部署을 다시 조회한다. 승인자 EMPLOYEE가 마지막 건을 처리해 배지가 0이 되면 카드가 사라진다.

### 원 요청과 달라진 점

- 원 요청은 대시보드에서 승인·반려를 하지 않는(조회 전용) 구성이었으나, 사용자 결정으로 승인자·ADMIN이 상세 모달에서 승인·반려할 수 있게 했다.
- 월간 휴가 캘린더(이전 §3-6, API-DASH-002·003)는 개편 시 삭제했다.
- 대시보드의 휴가 신청 모달 진입([休暇を申請])은 삭제했다. 신청은 SCR-004에서 한다.

- 프런트는 카드·버튼 노출만 제어한다. 승인·반려 권한과 `scope=all` 조회 권한(EMPLOYEE는 403)은 서버가 검증한다.

## 6. API

| 영역 | API |
|---|---|
| 통계·全社の出勤状況 | `GET /admin/dashboard/summary` (API-DASH-001, ADMIN) |
| 各部署の状況 | `GET /dashboard/department-status` (API-DASH-004, 공통) |
| 今日の出勤状況 | `GET /attendance/today` (API-ATT-003) |
| 출근 / 퇴근 | `POST /attendance/clock-in` (API-ATT-001), `POST /attendance/clock-out` (API-ATT-002) |
| 今月の勤務状況 | `GET /attendance/monthly` (API-ATT-007, `month` 생략) |
| 休暇の残り日数 | `GET /leaves/balance` (API-LEAVE-006) |
| 直近の申請履歴 | `GET /leaves/me?limit=3` (API-LEAVE-003) |
| 承認待ちの申請 | ADMIN `GET /leaves/pending-approval?scope=all&limit=5`, 승인자 `scope=mine&limit=5` (API-LEAVE-007) |
| 상세 / 승인 / 반려 / 취소 | `GET /leaves/:id`, `PATCH /leaves/:id/approve`, `PATCH /leaves/:id/reject`, `PATCH /leaves/:id/cancel` (API-LEAVE-004, 008, 009, 005) |

각 카드는 독립적으로 조회하며, 한 카드가 실패해도 다른 카드는 표시한다. 통계 카드와 全社の出勤状況은 같은 조회 1회를 공유한다.

## 7. 상태 처리

공통 규칙(03 Common UI Rules)을 따르며 화면 고유 사항은 다음과 같다.

| 各部署 Empty | 表示できる部署がありません。 |
| 直近の申請履歴 Empty | 申請履歴はありません。 |
| 비근무일(토·일·일본 공휴일) | 全社·各部署에 「本日は休日のため、出勤者のみ集計しています。」 (未出勤·休暇는 0) |
| 출근율 분모 0 | 「—」 |
| 부여 연차 미등록 | 「付与日数が登録されていません。」 안내. 판정은 `grantedDays === 0` |
| 409 ALREADY_CLOCKED_IN | 이미 출근이 등록되었습니다. (오늘 근태 다시 조회) |
| 409 NOT_CLOCKED_IN | 오늘 출근 기록이 없습니다. (오늘 근태 다시 조회) |

## 8. 완료 조건

- 개인 카드(今日·今月·休暇·直近)는 로그인한 사용자 본인의 데이터만 표시한다. 各部署の状況은 모든 사용자에게 부서별 숫자만 표시한다(개인 식별 정보 없음).
- 출근 및 퇴근 처리가 가능하고, 退勤時刻(퇴근 전 「--:--」)과 근무 진행률이 3-4 규칙대로 표시된다.
- 휴가 잔여(残日数·承認済み日数)가 서버 계산값대로 표시된다. 대시보드에는 휴가 신청 버튼이 없다.
- 承認待ちの申請은 ADMIN에게 전체, 승인자에게 본인 할당분만 표시되며, 상세 모달에서 승인 또는 반려할 수 있다. 할당이 없는 EMPLOYEE에게는 표시되지 않는다.
- ADMIN에게만 통계 카드와 全社の出勤状況이 표시된다.
- `xl` 이상과 미만에서 3-0의 배치·순서대로 표시되고, 360px 폭에서 화면 가로 넘침이 없다.
