# SCR-004: 휴가 관리

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-004 |
| 화면명 | 휴가 관리 |
| URL | 경로 기반 탭 3개: /leaves(自分の休暇, 기본) / /leaves/calendar(休暇カレンダー) / /leaves/approvals(承認, SCR-005). 이전 `?tab=`·`?year=` 파라미터는 무시 |
| 접근 권한 | 공통(承認 탭은 표시 대상만, 3.0 참조) |
| 관련 요구사항 | FR-LEAVE-001, FR-LEAVE-002, FR-LEAVE-003, FR-LEAVE-004, FR-LEAVE-005, FR-LEAVE-006 |

## 2. 화면 목적

사용자(ADMIN 포함)가 휴가를 신청하고, 본인의 신청 이력을 조회·취소하며, 승인 완료된 동료의 휴가 일정을 월 캘린더로 확인한다. 승인자·ADMIN은 같은 화면의 承認 탭에서 승인·반려한다(SCR-005).

## 3. 화면 구성

세 탭 공통으로 Page Header(휴가 아이콘 + 제목 「休暇管理」 + 우측 [＋ 休暇申請] 버튼, 좁은 폭에서도 한 줄) → 탭(自分の休暇 / 休暇カレンダー / 承認) → 탭 본문 순서로 표시한다. [休暇申請] 버튼은 어느 탭에서든 공통 휴가 신청 모달(3.2)을 연다.

### 3.0 탭

- 탭은 링크다(클라이언트 전환, 뒤로/앞으로로 탭 이동). 활성 탭은 `aria-current="page"`. 탭이 넘치면 탭 행만 가로 스크롤한다.
- 自分の休暇·休暇カレンダー는 모든 사용자에게 표시한다.
- 承認 탭: ADMIN은 항상 표시. 그 외는 본인에게 할당된 신청(`PENDING`·`APPROVED`·`REJECTED`)이 1건 이상일 때만 표시한다(`GET /leaves/pending-approval?scope=mine&status=PENDING,APPROVED,REJECTED&limit=1`의 `totalCount > 0`). 판정 전·조회 실패 시에는 숨긴다.
- `/leaves/approvals`에 직접 접근하면 판정 전에는 본문 대신 스켈레톤을 표시하고, 표시 대상이 아니면 `/leaves`로 replace한다(토스트 없음).
- 기존 `/leaves/approvals?scope=all` 링크(대시보드·상단바 벨)는 그대로 쓸 수 있다.

### 3.1 상단 요약 (自分の休暇)

- 카드 1장에 3구획: 有給休暇残日数(`remainingDays`) / 今年の取得日数(`approvedDays` + 「／ 付与日数 N日」) / 承認待ち(`pendingDays`) (API-LEAVE-006). `md` 미만은 세로 3행
- 다음 부여 예정일은 표시하지 않는다(데이터 없음, 사용자 결정)

### 3.2 공통 휴가 신청 모달

SCR-004에서 사용하는 공통 모달이다(SCR-002 휴가 카드의 신청 진입은 2026-11 대시보드 개편으로 삭제). 열 때마다 입력은 초기 상태로 시작한다. footer는 [キャンセル](텍스트) [申請する](채움)이다.

| 항목 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 휴가 종류 | Radio | O | 연차(ANNUAL) / 오전 반차(HALF_AM) / 오후 반차(HALF_PM) / 특별휴가(SPECIAL) / 기타(OTHER). 초기 선택 없음 |
| 시작일 | DatePicker | O | 휴가 시작일 |
| 종료일 | DatePicker | O | 휴가 종료일. 반차를 고르면 시작일과 같은 값으로 고정되고 비활성화 |
| 신청 일수 | Text | - | 주말을 제외한 일수 미리보기(반차 0.5). 최종 값은 서버가 계산 |
| 사유 | Textarea | O | 최대 500자, 글자 수 표시 |
| 승인자 | Searchable Select | 조건부 | 승인 필요 사용자에게만 표시되며 필수. 본인과 비활성 사용자는 후보에서 제외(API-LEAVE-002). 후보는 한 번 조회한 뒤 화면 안에서 이름·사원번호 부분 일치로 필터 |
| 신청 버튼 | Button | - | 申請する(모달 footer) |

- 승인 불필요 사용자(`user.approvalRequired = false`, 로그인 응답의 값)에게는 승인자 항목 대신 "신청 즉시 승인됩니다." 안내를 표시한다.

### 3.3 내 신청 이력 (自分の休暇, 「申請履歴」 카드)

신청일 내림차순으로 표시한다. 20건 페이지네이션.

| 항목 | 설명 |
|---|---|
| 申請日 | 신청 등록 날짜 |
| 休暇期間 | 시작일 ~ 종료일 |
| 休暇種別 | 신청한 휴가 종류 |
| 取得日数 | 신청 일수 |
| ステータス | 승인 대기 / 승인 / 반려 / 취소(연한 배지) |
| 操作 | [詳細] — 휴가 상세 모달 열기(취소 포함) |

- 승인자 열은 두지 않는다(승인자는 상세 모달에서 확인).

필터(카드 상단 한 줄, [検索] 클릭 시 적용):
- 申請期間: 시작일 `～` 종료일(date 입력 2개, 한쪽만 입력 가능, 미입력 = 전체). 신청일(Asia/Tokyo 날짜) 기준, 양끝 포함. 시작일 > 종료일이면 필드 아래 기간 순서 오류를 표시하고 검색하지 않는다
- 休暇種別: Select(すべて + 5종) / ステータス: Select(すべて + 4종). 단일 선택
- 연도 필터는 폐지했다(2026-11 사용자 결정, 신청일 범위로 대체)
- [検索]을 누르면 URL에 반영하고 1페이지로 돌아간다. 입력 중인 값은 [検索] 전까지 URL에 반영하지 않으며, 뒤로 가기 등으로 URL이 바뀌면 입력란도 URL 값으로 맞춘다.
- URL Query: `appliedFrom`, `appliedTo`, `leaveType`, `status`, `page`. 기본값은 URL에 쓰지 않는다. 실재하지 않는 날짜·미지 값은 버리고, 쉼표 복수 값은 첫 값만 쓴다. URL에서 `appliedFrom > appliedTo`이면 두 값을 모두 버린다. 이전 `year`는 무시한다.

좁은 폭(md 미만)에서는 표 대신 카드 목록으로 표시한다.

### 3.4 休暇カレンダー (`/leaves/calendar`)

승인 완료(`APPROVED`)된 활성 사원의 휴가를 월 캘린더와 목록으로 보여 준다(FR-LEAVE-005 공유 캘린더, API-LEAVE-010). 캘린더와 목록은 같은 응답 1회를 사용한다.

공개 항목: 이름, 사원번호, 부서, 기간, 공개용 분류(有給休暇 / 特別休暇 / 休暇), 반차 구분(午前·午後). 사유·일수·상태·승인자는 표시하지 않으며 상세 모달(4.4)로 이동하지 않는다.

조건(URL Query에 유지):
- 월: `‹ YYYY年MM月 ›`(前月·翌月 버튼). `month`(기본 이번 달, 미기재)
- 부서: Select(「全ての部署」 + 부서 목록, API-DEPT-001). `departmentId`
- 名前検索 / 社員番号検索: 검색 입력(부분 일치). `name`, `empId`. 입력이 300ms 멈추면 반영(replace, 기록을 늘리지 않음)
- 월 이동·부서 변경은 push. 조건은 모두 AND
- 모바일 전용: `date`(선택일), `view=month`(월 전체 목록)

공통 셀 규칙:
- 일요일 시작 주 단위 그리드. 일요일·공휴일 날짜는 `calendar-sunday`, 토요일은 `calendar-saturday` 색. 월 밖 날짜는 회색 숫자이며 일정은 표시하지 않는다
- 오늘 날짜는 원형 강조. 공휴일 판정·이름은 서버 응답(`holidays`)을 쓴다(PC는 날짜 옆에 공휴일명 표시, 모바일은 날짜 색만 바꾸고 이름은 셀의 `title`로만 제공)
- 휴가 막대는 신청 기간(주말 포함) 그대로 연결해 그리고, 주가 바뀌면 끊어 다음 주에 이어 그린다. 분류 색: PAID·OTHER = `leave-paid`, SPECIAL = `leave-special`

PC(`md` 이상. `xl` 이상은 좌우 2열, 그 미만은 세로 배치):
- 상단 행: 월 이동 + 부서 Select | 우측 名前検索·社員番号検索
- 좌: 캘린더. 막대 = 이름 + 반차 「（午前）」「（午後）」. 셀당 최대 2단, 넘치면 「+N件」. 막대 클릭 → 그 1건, 「+N件」 클릭 → 그 날짜 전원을 날짜별 휴가자 모달(氏名·社員番号·部署·期間·種別, API 호출 없음)로 표시
- 우: 「休暇予定一覧 YYYY年MM月」 카드. 社員番号 / 氏名 / 部署 / 休暇期間 / 休暇種別. 시작일 오름차순(서버 순서). 캘린더와 같은 높이로 맞추고 표 영역만 세로 스크롤(헤더 고정). 하단 안내 「ⓘ 承認済みの休暇が表示されます。」

모바일(`md` 미만, 320px까지 페이지 가로 스크롤 없음):
- 순서: 월 이동(가운데) → 부서 Select → 名前検索·社員番号検索(2열, 항상 표시. 검색 토글 없음) → 캘린더 → 범례(「休暇（有給休暇など）」「特別休暇（慶弔・リフレッシュなど）」) → 휴가자 목록 카드
- 셀: 7열 균등. 일정은 1단 칩만(이름 없음, 라벨은 PAID·OTHER 「休暇」 / SPECIAL 「特別休暇」. 아이콘은 2칸 이상 걸치는 막대에만) + 나머지 「+N件」. 셀 전체가 날짜 선택 버튼(접근성 이름에 날짜와 인원 수). 선택일은 테두리·배경 강조
- 선택일 기본값: 표시 월에 오늘이 있으면 오늘, 없으면 1일. 월을 이동하면 선택일을 초기화한다
- 목록 카드: 「M月D日（曜）の休暇予定」 + 인원 「N名」 + 세그먼트 [選択日 | 月全体]. 항목: 氏名 / 「社員番号：00001 | 部署」 / 분류 배지 / 「期間 …（N日間）」(반차는 「（半日）」)

## 4. 화면 동작

### 4.1 휴가 신청

1. [休暇申請] 버튼으로 공통 휴가 신청 모달을 열고 항목을 입력한다.
2. [申請する] 버튼을 클릭한다.
3. 입력값을 검증한다.
4. 신청 API를 호출한다(요청 중 버튼 비활성화).
5. 성공하면 토스트를 표시하고 모달을 닫은 뒤, 현재 탭에 머문 채로 데이터를 다시 조회한다.
   - 自分の休暇: 상단 요약과 내 신청 이력을 다시 조회한다. 검색 조건(필터·페이지)은 유지한다(이전의 「필터 초기화·`year` 이동」 규칙은 연도 필터 폐지와 함께 삭제).
   - 休暇カレンダー: 캘린더를 다시 조회한다(즉시 승인 건이 바로 반영됨).
   - PENDING: "휴가가 신청되었습니다. 승인자의 승인을 기다립니다."
   - APPROVED(즉시 승인): "휴가가 승인되었습니다."

### 4.2 이력 조회

- 화면 진입 시와 필터 변경 시 내 휴가 이력 API를 호출한다. 페이지네이션은 03 공통 규칙을 따른다.
- 조건·페이지를 바꾸는 동안은 이전 목록을 남겨 둔다(결과가 오면 교체).

### 4.2-1 캘린더 조회

- 탭 진입 시와 월·부서·이름·사원번호 변경 시 API-LEAVE-010을 호출한다. 월 이동 중에는 이전 달 데이터를 흐리게 남겨 둔다.
- 이 API는 페이지네이션 없이 그 달 전체를 받는다(NFR-002 예외).

### 4.3 휴가 취소

1. 휴가 상세 모달에서 [취소] 버튼을 클릭한다.
2. 확인 단계("휴가 신청을 취소하시겠습니까?", 버튼 [돌아가기] [취소하기])
3. 취소 API를 호출한다.
4. 성공하면 토스트("휴가 신청을 취소했습니다.")를 표시하고 모달을 닫은 뒤 목록과 상단 요약을 다시 조회한다.

[취소] 버튼은 신청자 본인이 보고 있고, 다음 중 하나일 때만 표시한다(FR-LEAVE-004).
- 상태가 PENDING
- 즉시 승인 건(`status = APPROVED`, `autoApproved = true`)이고 시작일이 오늘보다 뒤임(시작일 > 오늘)

### 4.4 휴가 상세 모달 (공통 컴포넌트)

SCR-002, SCR-004, SCR-005에서 같은 모달을 사용한다(API-LEAVE-004).

| 항목 | 설명 |
|---|---|
| 신청자 | 이름, 사원번호, 부서 |
| 휴가 종류, 기간, 일수 | - |
| 사유 | 신청 사유 |
| 승인자 | 이름. 즉시 승인 건은 "자동 승인" |
| 상태 | - |
| 처리자 / 처리 시간 | 처리된 건만 표시 |
| 반려 사유 | REJECTED만 표시 |
| 버튼 | 신청자: [취소](조건부) / 할당된 승인자 또는 ADMIN, 그리고 PENDING이며 본인 신청이 아닌 경우: [승인] [반려] / [닫기] |

## 5. 입력값 검증

| 조건 | 메시지 |
|---|---|
| 휴가 종류 필수 | 휴가 종류를 선택해주세요. |
| 시작일·종료일 필수 | 휴가 기간을 입력해주세요. |
| 종료일 ≥ 시작일 | 종료일은 시작일보다 빠를 수 없습니다. |
| 기간 전체가 주말 | 신청 기간에 근무일이 없습니다. |
| 사유 필수, 최대 500자 | 사유를 입력해주세요. / 사유는 500자 이내로 입력해주세요. |
| 승인 필요 사용자의 승인자 필수 | 승인자를 선택해주세요. |

## 6. 예외 처리

| 응답 | 처리 |
|---|---|
| 400 INVALID_DATE_RANGE / NO_WORKING_DAYS | 해당 필드 아래 오류 메시지 |
| 400 APPROVER_REQUIRED / INVALID_APPROVER | 승인자 필드 오류 "승인자를 다시 선택해주세요." 후 후보 목록 다시 조회 |
| 409 LEAVE_CONFLICT | 토스트: 해당 기간에 이미 신청된 휴가가 있습니다. |
| 422 INSUFFICIENT_LEAVE_BALANCE | 토스트: 잔여 연차가 부족합니다. (잔여 n일) 후 상단 요약 다시 조회 |
| 409 NOT_CANCELLABLE | 취소할 수 없는 상태입니다. (목록 다시 조회) |

인증 만료, 권한 오류, 서버 오류, 중복 클릭은 03 Common UI Rules를 따른다.

## 7. API 연동

| 기능 | API |
|---|---|
| 상단 요약 | `GET /leaves/balance` (API-LEAVE-006) |
| 승인자 후보 | `GET /leaves/approvers` (API-LEAVE-002) |
| 휴가 신청 | `POST /leaves` (API-LEAVE-001) |
| 내 신청 이력 | `GET /leaves/me?appliedFrom&appliedTo&leaveType&status&page&limit=20` (API-LEAVE-003) |
| 상세 | `GET /leaves/:id` (API-LEAVE-004) |
| 취소 | `PATCH /leaves/:id/cancel` (API-LEAVE-005) |
| 휴가 캘린더 | `GET /leaves/calendar?month&departmentId&name&empId` (API-LEAVE-010) |
| 부서 선택지 | `GET /departments` (API-DEPT-001) |
| 承認 탭 표시 판정 | `GET /leaves/pending-approval?scope=mine&status=PENDING,APPROVED,REJECTED&limit=1` (API-LEAVE-007, ADMIN은 호출 안 함) |
| 承認 탭 | SCR-005 §9 |

## 8. 권한

- 모든 사용자는 본인의 휴가만 신청·조회·취소할 수 있다.
- 다른 사용자의 휴가 상세는 이 화면에서 조회할 수 없다(승인 대상 휴가는 承認 탭(SCR-005)에서 조회).
- 休暇カレンダー는 모든 사용자에게 같은 내용을 보여 주며, 공개 항목(3.4)만 표시한다(FR-LEAVE-005).

## 9. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- 이력 Empty: 신청한 휴가가 없습니다.(필터 유무와 관계없이 같은 문구)
- 승인자 후보 Empty: 선택할 수 있는 승인자가 없습니다. 관리자에게 문의해주세요.
- 캘린더 Loading: 캘린더·목록 스켈레톤 / Error: 각 영역 [다시 시도]
- 캘린더 목록 Empty: 조건(부서·이름·사원번호) 있음 「条件に一致する休暇予定はありません。」, 조건 없음 「該当する休暇予定はありません。」, 모바일 선택일 「この日の休暇予定はありません。」. 0건이어도 캘린더 그리드(공휴일 포함)는 표시한다

## 10. 완료 조건

- 승인 필요 사용자는 승인자를 지정해 PENDING으로 신청된다.
- 승인 불필요 사용자는 승인자 없이 즉시 APPROVED로 신청된다.
- 잔여 연차 초과와 날짜 중복 신청이 차단된다.
- 신청 결과가 이력과 상단 요약에 반영된다.
- 조건에 맞는 휴가만 취소할 수 있다.
- 입력 오류와 서버 오류가 적절히 처리된다.
- 休暇カレンダー에는 승인 완료·활성 사원 휴가만 공개 항목으로 표시되고, 캘린더와 목록 내용이 일치한다.
- 承認 탭은 표시 대상(3.0)에게만 보이고, 대상이 아닌 사용자의 직접 접근은 `/leaves`로 돌아간다.
