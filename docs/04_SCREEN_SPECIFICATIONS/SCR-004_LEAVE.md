# SCR-004: 휴가 관리

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-004 |
| 화면명 | 휴가 관리 |
| URL | /leaves (탭 없음. 이전 `?tab=` 파라미터는 무시) |
| 접근 권한 | 공통 |
| 관련 요구사항 | FR-LEAVE-001, FR-LEAVE-004, FR-LEAVE-005, FR-LEAVE-006 |

## 2. 화면 목적

사용자(ADMIN 포함)가 휴가를 신청하고, 본인의 신청 이력을 조회·취소한다.

## 3. 화면 구성

Page Header(제목 + 우측 [休暇申請] 버튼, `sm` 미만에서는 제목 아래) → 상단 요약 → 내 신청 이력 순서로 표시한다. [休暇申請] 버튼은 공통 휴가 신청 모달(3.2)을 연다.

### 3.1 상단 요약

- 올해 부여 연차 / 승인 완료 / 승인 대기 / 잔여 연차 (API-LEAVE-006)

### 3.2 공통 휴가 신청 모달

SCR-004에서 사용하는 공통 모달이다(SCR-002 휴가 카드의 신청 진입은 2026-11 대시보드 개편으로 삭제). 열 때마다 입력은 초기 상태로 시작한다. footer는 [キャンセル](텍스트) [申請する](채움)이다.

| 항목 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 휴가 종류 | Radio | O | 연차(ANNUAL) / 오전 반차(HALF_AM) / 오후 반차(HALF_PM) / 특별휴가(SPECIAL) / 기타(OTHER). 초기 선택 없음 |
| 시작일 | DatePicker | O | 휴가 시작일 |
| 종료일 | DatePicker | O | 휴가 종료일. 반차를 고르면 시작일과 같은 값으로 고정되고 비활성화 |
| 신청 일수 | Text | - | 주말을 제외한 일수 미리보기(반차 0.5). 최종 값은 서버가 계산 |
| 사유 | Textarea | O | 최대 500자, 글자 수 표시 |
| 승인자 | Searchable Select | 조건부 | 승인 필요 사용자에게만 표시되며 필수. 본인과 비활성 사용자는 후보에서 제외(API-LEAVE-002). 후보는 한 번 조회한 뒤 화면 안에서 이름·사원번호 부분 일치로 필터 |
| 신청 버튼 | Button | - | 申請する(모달 footer) |

- 승인 불필요 사용자(`user.approvalRequired = false`, 로그인 응답의 값)에게는 승인자 항목 대신 "신청 즉시 승인됩니다." 안내를 표시한다.

### 3.3 내 신청 이력

신청일 내림차순으로 표시한다.

| 항목 | 설명 |
|---|---|
| 신청일 | 신청 등록 날짜 |
| 휴가 종류 | 신청한 휴가 종류 |
| 기간 | 시작일 ~ 종료일 |
| 일수 | 신청 일수 |
| 승인자 | 승인자 이름. 즉시 승인 건은 "자동 승인" |
| 상태 | 승인 대기 / 승인 / 반려 / 취소 |
| 상세 | 휴가 상세 모달 열기 |

필터:
- 연도: Select(기본 올해, 선택지는 올해+1 ~ 올해−4)
- 상태: 토글 버튼 복수 선택(승인 대기 / 승인 / 반려 / 취소, 목록 배지와 같은 색)
- 휴가 종류: 토글 버튼 복수 선택(5종)
- 상태·종류는 선택하지 않으면 전체를 표시한다(안내 "選択しない場合はすべて表示します。"). 누르는 즉시 URL에 반영하고 1페이지로 돌아간다.
- URL Query: `year`, `status`, `leaveType`(쉼표 구분, 예: `?status=PENDING,APPROVED&leaveType=HALF_AM`), `page`. 미지 값·중복은 버린다. 기본값은 URL에 쓰지 않는다.

좁은 폭(md 미만)에서는 표 대신 카드 목록으로 표시한다.

## 4. 화면 동작

### 4.1 휴가 신청

1. [休暇申請] 버튼으로 공통 휴가 신청 모달을 열고 항목을 입력한다.
2. [申請する] 버튼을 클릭한다.
3. 입력값을 검증한다.
4. 신청 API를 호출한다(요청 중 버튼 비활성화).
5. 성공하면 토스트를 표시하고 모달을 닫은 뒤 상단 요약과 내 신청 이력을 다시 조회한다.
   - 이동 URL: `/leaves?year=<시작일의 연도>`(올해이면 `year` 생략). 상태·종류·페이지 필터는 초기화한다. 이동 URL로 조회 조건이 바뀌지 않으면 이력을 그 자리에서 다시 조회한다.
   - PENDING: "휴가가 신청되었습니다. 승인자의 승인을 기다립니다."
   - APPROVED(즉시 승인): "휴가가 승인되었습니다."

### 4.2 이력 조회

- 화면 진입 시와 필터 변경 시 내 휴가 이력 API를 호출한다. 페이지네이션은 03 공통 규칙을 따른다.

### 4.3 휴가 취소

1. 휴가 상세 모달에서 [취소] 버튼을 클릭한다.
2. 확인 단계("휴가 신청을 취소하시겠습니까?", 버튼 [돌아가기] [취소하기])
3. 취소 API를 호출한다.
4. 성공하면 토스트("휴가 신청을 취소했습니다.")를 표시하고 모달을 닫은 뒤 목록과 상단 요약을 다시 조회한다.

[취소] 버튼은 신청자 본인이 보고 있고, 다음 중 하나일 때만 표시한다(FR-LEAVE-004).
- 상태가 PENDING
- 즉시 승인 건(`status = APPROVED`, `autoApproved = true`)이고 시작일이 오늘보다 뒤임(시작일 > 오늘)

### 4.4 휴가 상세 모달 (공통 컴포넌트)

SCR-002, SCR-004, SCR-005에서 같은 모달을 사용한다(API-LEAVE-004).

| 항목 | 설명 |
|---|---|
| 신청자 | 이름, 사원번호, 부서 |
| 휴가 종류, 기간, 일수 | - |
| 사유 | 신청 사유 |
| 승인자 | 이름. 즉시 승인 건은 "자동 승인" |
| 상태 | - |
| 처리자 / 처리 시간 | 처리된 건만 표시 |
| 반려 사유 | REJECTED만 표시 |
| 버튼 | 신청자: [취소](조건부) / 할당된 승인자 또는 ADMIN, 그리고 PENDING이며 본인 신청이 아닌 경우: [승인] [반려] / [닫기] |

## 5. 입력값 검증

| 조건 | 메시지 |
|---|---|
| 휴가 종류 필수 | 휴가 종류를 선택해주세요. |
| 시작일·종료일 필수 | 휴가 기간을 입력해주세요. |
| 종료일 ≥ 시작일 | 종료일은 시작일보다 빠를 수 없습니다. |
| 기간 전체가 주말 | 신청 기간에 근무일이 없습니다. |
| 사유 필수, 최대 500자 | 사유를 입력해주세요. / 사유는 500자 이내로 입력해주세요. |
| 승인 필요 사용자의 승인자 필수 | 승인자를 선택해주세요. |

## 6. 예외 처리

| 응답 | 처리 |
|---|---|
| 400 INVALID_DATE_RANGE / NO_WORKING_DAYS | 해당 필드 아래 오류 메시지 |
| 400 APPROVER_REQUIRED / INVALID_APPROVER | 승인자 필드 오류 "승인자를 다시 선택해주세요." 후 후보 목록 다시 조회 |
| 409 LEAVE_CONFLICT | 토스트: 해당 기간에 이미 신청된 휴가가 있습니다. |
| 422 INSUFFICIENT_LEAVE_BALANCE | 토스트: 잔여 연차가 부족합니다. (잔여 n일) 후 상단 요약 다시 조회 |
| 409 NOT_CANCELLABLE | 취소할 수 없는 상태입니다. (목록 다시 조회) |

인증 만료, 권한 오류, 서버 오류, 중복 클릭은 03 Common UI Rules를 따른다.

## 7. API 연동

| 기능 | API |
|---|---|
| 상단 요약 | `GET /leaves/balance` (API-LEAVE-006) |
| 승인자 후보 | `GET /leaves/approvers` (API-LEAVE-002) |
| 휴가 신청 | `POST /leaves` (API-LEAVE-001) |
| 내 신청 이력 | `GET /leaves/me` (API-LEAVE-003) |
| 상세 | `GET /leaves/:id` (API-LEAVE-004) |
| 취소 | `PATCH /leaves/:id/cancel` (API-LEAVE-005) |

## 8. 권한

- 모든 사용자는 본인의 휴가만 신청·조회·취소할 수 있다.
- 다른 사용자의 휴가는 이 화면에서 조회할 수 없다(승인 대상 휴가는 SCR-005에서 조회).

## 9. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- 이력 Empty: 신청한 휴가가 없습니다.
- 승인자 후보 Empty: 선택할 수 있는 승인자가 없습니다. 관리자에게 문의해주세요.

## 10. 완료 조건

- 승인 필요 사용자는 승인자를 지정해 PENDING으로 신청된다.
- 승인 불필요 사용자는 승인자 없이 즉시 APPROVED로 신청된다.
- 잔여 연차 초과와 날짜 중복 신청이 차단된다.
- 신청 결과가 이력과 상단 요약에 반영된다.
- 조건에 맞는 휴가만 취소할 수 있다.
- 입력 오류와 서버 오류가 적절히 처리된다.
