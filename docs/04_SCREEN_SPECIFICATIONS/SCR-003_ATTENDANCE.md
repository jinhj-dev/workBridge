# SCR-003: 근태 관리

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-003 |
| 화면명 | 근태 관리 |
| URL | /attendance |
| 접근 권한 | 공통 |
| 관련 요구사항 | FR-ATT-003 |

## 2. 화면 목적

로그인한 사용자가 본인의 근태 이력을 기간별로 조회한다.

## 3. 검색 조건

| 요소 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 시작일 | Date Picker | O | 조회 시작일 (기본: 이번 달 1일) |
| 종료일 | Date Picker | O | 조회 종료일 (기본: 오늘) |
| 상태 | 토글 버튼(복수 선택) | - | 근무 중 / 퇴근 완료 / 퇴근 누락 버튼을 눌러 선택·해제한다. 선택한 상태 중 하나라도 일치하는 기록을 표시하고, 아무것도 선택하지 않으면 전체 상태를 표시한다(기본: 선택 없음). 버튼 색은 목록의 상태 배지와 같다(근무 중 초록, 퇴근 완료 회색, 퇴근 누락 빨강). 버튼을 누르는 즉시 목록이 갱신된다(조회 버튼 불필요). 이때 기간은 마지막으로 조회한 값을 쓰고, 입력만 하고 조회하지 않은 기간은 반영하지 않는다 |
| 조회 버튼 | Button | - | 검색 실행 |

## 4. 목록 구성

근무일 내림차순으로 표시한다.

| 컬럼 | 설명 |
|---|---|
| 근무일 | 근무 날짜 (요일 포함) |
| 출근 시간 | 출근 등록 시간 |
| 퇴근 시간 | 퇴근 등록 시간. 없으면 `—` |
| 근무 시간 | 출근부터 퇴근까지(시:분). 퇴근 전이면 `—` |
| 상태 | 근무 중 / 퇴근 완료 / 퇴근 누락 |
| 비고 | 관리자가 수정한 기록(`modifiedAt`이 있음)이면 "관리자 수정" 표시 |

- 퇴근 누락 기록은 강조 표시하고 "관리자에게 퇴근 시간 수정을 요청하세요." 툴팁을 표시한다(FR-ATT-002, FR-ATT-005).
- `md` 미만 폭에서는 표 대신 같은 항목의 카드 목록으로 표시한다. 툴팁 문구는 카드 안에 직접 표시한다.

## 5. 동작 명세

### 조회

1. 화면 진입 시 기본 기간으로 조회한다.
2. 시작일과 종료일을 입력하고 조회 버튼을 클릭한다(기간은 조회 버튼으로 반영). 상태 버튼은 누르는 즉시 1페이지부터 다시 조회한다.
3. 입력값을 검증한다.
4. 근태 이력 API를 호출한다.
5. 조회 결과를 목록에 표시한다.

페이지네이션은 03 Common UI Rules를 따른다.

## 6. 유효성 검증

| 조건 | 메시지 |
|---|---|
| 시작일·종료일 필수 | 조회 기간을 입력해주세요. |
| 시작일 ≤ 종료일 | 시작일은 종료일보다 늦을 수 없습니다. |
| 최대 조회 기간 이내(FR-ATT-003) | 조회 기간은 최대 1년입니다. |

조회 대상은 서버에서 로그인한 사용자 본인으로 제한한다(요청 파라미터로 다른 사용자를 지정할 수 없다).

URL Query의 기간이 형식은 맞지만 순서 또는 최대 기간 규칙을 위반하면 기본 기간으로 바꾸지 않고 해당 검증 메시지를 표시하며, 목록 카드를 숨기고 API를 호출하지 않는다.

## 7. API

`GET /api/v1/attendance` (API-ATT-004)

Query: `startDate`, `endDate`, `status`(쉼표로 구분한 복수 값, 예: `DONE,MISSING_CLOCK_OUT`), `page`, `limit`

## 8. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- Empty: 조회 기간에 근태 기록이 없습니다. 상태를 선택한 경우에는 "조건에 일치하는 근태 기록이 없습니다."
- 400 INVALID_DATE_RANGE: 검증 메시지와 같은 문구 표시

## 9. 완료 조건

- 본인의 근태 기록만 조회할 수 있다.
- 기간별 검색이 가능하다.
- 상태를 복수 선택해 검색할 수 있고, 검색 조건(기간·상태)과 페이지는 URL Query에 유지된다.
- 퇴근 누락 기록이 구분되어 표시된다.
- 페이지네이션이 정상 작동한다.
