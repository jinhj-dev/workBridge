# SCR-007: 사원 상세

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-007 |
| 화면명 | 사원 상세 |
| URL | /admin/users/:id |
| 접근 권한 | 관리자 |
| 관련 요구사항 | FR-USER-002, FR-LEAVE-006 |

## 2. 화면 목적

관리자가 사원 정보를 조회하고 수정한다.
휴가 승인 정책, 계정 상태, 연도별 부여 연차를 관리한다.

## 3. 화면 구성

### 3.1 기본 정보

| 요소 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 이름 | Input | O | 최대 100자 |
| 사원번호 | Input | O | 숫자만, 최대 50자리, 중복 불가 |
| 입사일 | Date | O | 미래 날짜 허용 |
| 부서 | Select | O | 소속 부서(未所属 포함). 부서 없음으로 바꿀 수 없다 |
| 권한 | Select | O | ADMIN / EMPLOYEE |
| 휴가 승인 필요 여부 | Switch | O | 필요 / 불필요 |
| 계정 상태 | Switch | O | 활성 / 비활성 |
| 등록일 / 수정일 | Text | - | 읽기 전용 |
| 비밀번호 변경 필요 | Text | - | 읽기 전용 (최초 로그인 전이면 "변경 필요") |

버튼: [저장] [취소] [목록으로]

- [취소]: 변경 내용을 버리고 마지막으로 조회한 값으로 되돌린다.
- [목록으로]: `/admin/users`로 이동하며 이전 검색 조건을 유지한다. 저장하지 않은 변경이 있으면 "저장하지 않은 변경 사항이 있습니다. 이동하시겠습니까?" 확인 모달을 표시한다.

### 3.2 부여 연차

| 요소 | 타입 | 설명 |
|---|---|---|
| 연도 | Select | 올해 기본, 전년·다음 해 선택 가능 |
| 부여 일수 | Number Input | 0 이상, 0.5 단위 |
| 저장 버튼 | Button | 해당 연도 부여 연차 저장 |

등록된 연도별 부여 연차 목록(연도, 부여 일수)을 함께 표시한다.

## 4. 승인 정책

승인 필요 여부에 따른 신청 처리 방식과 변경 시 소급하지 않는 규칙은 02_REQUIREMENTS의 FR-LEAVE-001과 업무 규칙을 따른다.

- 저장 시 승인 필요 여부가 바뀌면 "이후 신규 신청부터 적용됩니다." 안내를 함께 표시한다.

## 5. 동작 명세

### 조회

1. URL의 사용자 ID로 사원 상세를 조회한다.
2. 조회 결과를 화면에 표시한다.
3. 사용자가 존재하지 않으면 "사원을 찾을 수 없습니다." 안내와 [목록으로] 버튼을 표시한다.

### 수정

1. 정보를 변경한다.
2. 저장 버튼을 클릭한다.
3. 입력값을 검증한다.
4. 계정 상태를 활성에서 비활성으로 바꾼 경우 확인 모달을 표시한다.
   - "비활성화하면 이 사원은 로그인할 수 없고, 이 사원이 신청한 승인 대기 휴가는 취소됩니다."
   - 이 사원에게 할당된 승인 대기 건이 있으면(`pendingApprovalCount > 0`) "이 사원에게 할당된 승인 대기 {n}건은 관리자가 대리 처리해야 합니다." 경고를 추가한다.
5. 사원 수정 API 호출
6. 성공 시 토스트 "저장되었습니다."를 표시하고 화면 정보 갱신

### 부여 연차 저장

1. 연도와 부여 일수를 입력하고 저장 버튼을 클릭한다.
2. 부여 연차 API를 호출한다.
3. 성공 시 토스트를 표시하고 부여 연차 목록을 갱신한다.

## 6. 유효성 검증

| 조건 | 메시지 |
|---|---|
| 이름 필수 | 이름을 입력해주세요. |
| 사원번호 필수 | 사원번호를 입력해주세요. |
| 사원번호 숫자만 | 사원번호는 숫자로 입력해주세요. |
| 입사일 필수 | 입사일을 선택해주세요. |
| 부서 필수 | 部署を選択してください。 |
| 부여 일수 0 이상, 0.5 단위 | 부여 일수는 0.5일 단위로 입력해주세요. |

서버 검증: 사원번호 중복, 존재하는 부서, 권한 값, 마지막 활성 ADMIN 보호(FR-USER-002)

## 7. API

| 기능 | API |
|---|---|
| 사원 상세 | `GET /admin/users/:id` (API-USER-003) |
| 사원 수정 | `PATCH /admin/users/:id` (API-USER-004) |
| 부여 연차 저장 | `PUT /admin/users/:id/leave-grants/:year` (API-USER-005) |
| 부서 목록 | `GET /departments` (API-DEPT-001) |

## 8. 권한 및 예외

- ADMIN만 접근할 수 있으며 서버에서도 검증한다.

| 응답 | 처리 |
|---|---|
| 404 NOT_FOUND | 사원을 찾을 수 없습니다. |
| 409 DUPLICATE_EMP_ID | 사원번호 필드 아래 "이미 사용 중인 사원번호입니다." |
| 409 LAST_ADMIN | 마지막 관리자 계정은 비활성화하거나 권한을 변경할 수 없습니다. (값 되돌림) |
| 400 INVALID_DEPARTMENT | 부서를 다시 선택해주세요. |

## 9. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- 부여 연차 Empty: 등록된 부여 연차가 없습니다.

## 10. 완료 조건

- 사원 상세 조회와 정보 수정이 가능하다.
- 승인 정책 변경이 이후 신규 휴가 신청에만 반영된다.
- 비활성화 시 로그인 차단과 PENDING 신청 취소가 처리된다.
- 마지막 활성 ADMIN은 비활성화·강등되지 않는다.
- 연도별 부여 연차를 등록·수정할 수 있다.
