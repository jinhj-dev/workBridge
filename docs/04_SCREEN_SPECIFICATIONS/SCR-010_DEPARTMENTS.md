# SCR-010: 부서 관리

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-010 |
| 화면명 | 부서 관리(部署管理) |
| URL | /admin/departments |
| 접근 권한 | 관리자 |
| 관련 요구사항 | FR-DEPT-001 |

## 2. 화면 목적

관리자가 부서를 조회·검색·정렬하고, 등록·수정·삭제한다. 부서별 책임자·설명·소속 사원을 확인한다.

## 3. 화면 구성

위에서 아래 순서로 배치한다.

| 영역 | 구성 |
|---|---|
| 헤더 | `PageHeader`(제목 「部署管理」) + 우측 [部署を追加](등록 모달 열기). 아래에 설명 「部署情報の確認・追加・編集・削除を行います。」 |
| 요약 | `StatCard` 2개(`sm` 이상 2열, 미만 1열). 「部署数」(N部署, 未所属 제외) / 「所属社員数」(N名, 전체 활성 사원). API-DEPT-007 |
| 部署一覧 | `Card`(제목 「部署一覧」). 헤더 우측에 검색·정렬·조건 초기화(아래), 본문에 목록·안내·페이지네이션 |

- 목록 아래의 「選択中の部署情報」 영역은 두지 않는다. 부서 상세는 행의 [詳細]로 여는 部署詳細 모달(§4)에서 확인한다.

部署一覧 헤더의 검색·조작 요소(넘치면 다음 줄로 내린다)

| 요소 | 타입 | 설명 |
|---|---|---|
| 部署名 | `SearchInput` | placeholder 「部署名で検索」. 부분 일치, 대소문자 무시, 최대 100자. 입력이 300ms 멈추면 자동 반영(검색 버튼 없음) |
| 並び替え | Select | `md` 미만에서만 표시(§4 정렬 옵션). `md` 이상은 표 열 제목으로 정렬 |
| 条件をクリア | Button | 검색어·정렬·페이지를 모두 초기화. 조건이 없으면 비활성 |

- 범위 밖: 이번 달 변경 수, 상태(유효) 필터·배지, 부서 코드 검색 입력, 책임자로 검색·정렬, 부서 계층.

## 4. 목록 구성

`md` 이상은 표, 미만은 같은 항목의 카드 목록으로 표시한다(SCR-008과 같음). 목록 아래에 안내 박스(정보 아이콘)를 표시한다.

- 「※ 社員は1つの部署にのみ所属します。」「※ 所属社員がいる部署は削除できません。」「※ 部署の階層（親子関係）は使用しません。」「所属社員数は有効な社員のみを数えます。」

| 컬럼 | 정렬 | 설명 |
|---|---|---|
| 部署名 | O | 건물 아이콘 + 부서명(Bold) + 아래 줄에 부서 코드. 시스템 부서(`isSystem = true`, 未所属)는 옆에 `Badge` neutral 「システム」. 표시 전용(클릭·선택 없음) |
| 部署責任者 | | 책임자 이름. 없으면 「—」 |
| 所属社員数 | O | 활성 사원 수(`memberCount`), 「N名」 + 옆에 [確認](secondary). 우측 정렬. [確認]은 0명이어도 누를 수 있고 所属社員確認 모달(§5)을 연다 |
| 説明 | | 1줄 말줄임(전체는 `title` 툴팁). 없으면 「—」 |
| 更新日 | O | 수정일(Asia/Tokyo 날짜) |
| 操作 | | [詳細](secondary)[編集](primary outline)[削除](Danger outline). 열 제목은 화면에 보이지 않는다(스크린리더 전용). 시스템 부서 행은 [詳細]만 표시한다 |

- 행 버튼(확인·상세·편집·삭제)은 높이 36px·간격 8px로 통일하고 줄바꿈하지 않는다.
- 버튼 접근성 이름: 「部署「{name}」の所属社員を確認」「部署「{name}」の詳細を表示」「部署「{name}」を編集」「部署「{name}」を削除」
- 표(`md` 이상)는 최대 5행 높이(헤더 44px + 행 52px × 5 = 304px)로 제한하고, 넘치면 표 영역 안에서만 세로 스크롤한다. 헤더 행은 스크롤해도 고정(sticky)한다. 5건 이하면 스크롤바가 생기지 않는다. 페이지네이션(20건)·검색·정렬은 그대로이며 높이만 제한한다.
- 카드 목록(`md` 미만): 部署名 / 「部署責任者: {name}」 / 「所属社員数 N名 [確認]」 / 「更新日 {date}」 / 설명(최대 2줄, 없으면 줄 생략) / 버튼. 375px에서 가로 스크롤이 생기지 않게 줄바꿈한다.
  - 카드 목록에는 내부 스크롤을 적용하지 않고 페이지 스크롤 + 페이지네이션을 유지한다. 카드 1장이 약 200px라 5장 높이(약 1000px)의 내부 스크롤은 좁은 화면에서 이점이 없고 터치 스크롤과 충돌(스크롤 트랩)하기 때문이다.

### 정렬

- 표: 정렬 가능한 열 제목의 버튼(`aria-sort`, 위·아래 화살표)을 누른다. 같은 열을 다시 누르면 오름차순↔내림차순, 다른 열을 누르면 그 열의 기본 방향(部署名 오름차순, 所属社員数 내림차순, 更新日 내림차순)으로 바꾼다.
- 카드 목록의 並び替え 옵션: 部署名（昇順）/（降順）, 所属社員数（多い順）/（少ない順）, 更新日（新しい順）/（古い順）
- 기본 정렬은 部署名 오름차순이다. 동률은 부서 코드 오름차순(서버).

### 部署詳細 모달

- 행의 [詳細] 클릭 시 모달(큰 폭, 제목 「部署詳細」)을 연다. 조회 전용이며 목록 행 데이터를 그대로 표시한다(추가 API 호출 없음). 未所属도 열 수 있다.
- 본문: 왼쪽에 건물 아이콘(원형)·부서명·「システム」 배지(시스템 부서), 오른쪽에 `DetailTable`(`md` 미만은 세로 배치).

  | 행 | 내용 |
  |---|---|
  | 部署コード | 부서 코드 |
  | 部署責任者 | 「{name}（{empId}）」. 없으면 「未設定」 |
  | 所属社員数 | 「N名」 |
  | 無効の社員数 | 「N名」. `inactiveMemberCount > 0`일 때만 표시 |
  | 説明 | 줄바꿈 그대로 표시. 없으면 「—」 |
  | 更新日 | 수정일 |

- footer: [閉じる] [この部署を編集](시스템 부서면 숨김). [この部署を編集]은 상세 모달을 닫고 등록·수정 모달(수정)을 연다.

## 5. 동작 명세

### 조회

1. 화면 진입 시 URL Query(`name`, `sort`, `order`, `page`)의 조건으로 목록(API-DEPT-002)과 요약(API-DEPT-007)을 조회한다. 없으면 조건 없음·部署名 오름차순·1페이지. 기본값인 조건은 URL에 넣지 않는다. 허용 외 `sort`·`order`는 기본값으로 해석한다(`order`만 잘못되면 그 열의 기본 방향). 이전 `code` Query는 읽지 않는다.
2. 부서명 입력은 앞뒤 공백을 제거해 300ms 후 URL에 반영하고(`replace`, 이력 추가 없음) 1페이지로 이동한다.
3. 정렬 변경은 1페이지로 이동한다(`push`). [条件をクリア]는 모든 Query를 제거한다.
4. 페이지네이션(20건)과 검색 조건 유지는 03 공통 규칙을 따른다. 결과가 0건이어도 전체 건수가 있으면(범위 밖 페이지) 페이지네이션을 표시한다.
5. 요약은 목록과 독립적으로 조회한다. 로딩 중 스켈레톤, 실패하면 수치 자리에 「—」(목록은 그대로 사용 가능).

### 등록·수정 (등록·수정 모달)

1. [部署を追加] 또는 [編集]·部署詳細 모달의 [この部署を編集] 클릭 시 모달(큰 폭)을 연다(제목 「部署の登録」/「部署の編集」). 수정 시 현재 값을 채운다. 열 때마다 입력값을 초기화한다.

   | 항목 | 타입 | 필수 | 설명 |
   |---|---|---|---|
   | 部署コード | Input | O | placeholder 「例: DEV」, 안내 「半角英数字とハイフン、20文字以内」. 서버가 대문자로 정규화한다 |
   | 部署名 | Input | O | 최대 100자 |
   | 説明（任意） | Textarea | | 최대 500자, 줄바꿈 허용 |
   | 部署責任者（任意） | Autocomplete | | 아래 참조. 안내 「入力欄を空にすると未設定になります。」 |

   部署責任者 입력(`ApproverSelect` 재사용, 서버 검색)
   - 모달이 열려 있는 동안 후보(API-DEPT-009)를 조회한다. 입력 문자는 300ms 멈춘 뒤 `keyword`로 서버에 보내 다시 조회한다(재조회 중에도 입력란 유지). 후보 0건이어도 입력란은 남기고 목록에 「該当する社員がいません。」를 표시한다.
   - placeholder 「氏名または社員番号で検索」, 옵션 「{name} ({empId}) / {departmentName}」. 후보 조회 실패 시 「社員の候補を読み込めませんでした。」와 [再試行].
   - 결과가 100건(상한)이면 안내 「社員番号順の先頭100名を表示しています。」를 표시한다.
   - 수정 시 현재 책임자는 후보에 없어도 선택된 상태로 표시한다(부서명 없이 「{name} ({empId})」).
   - 입력하면 선택이 해제된다. 문자를 남긴 채 선택하지 않고 포커스를 벗어나면 원래 선택으로 되돌린다. 입력란을 비우고 벗어나면 미설정(해제)이 된다.

2. footer: [キャンセル] [登録する]/[保存する]. Enter로도 제출할 수 있다(후보 목록이 열려 있으면 Enter는 후보 선택).
3. 입력값 검증(앞뒤 공백 제거 후) → 등록 `POST` / 수정 `PATCH`. 전송 항목은 code·name·description(빈 값은 null). managerId는 등록 시 항상(미선택이면 null), 수정 시에는 책임자를 바꾼 경우에만 보낸다(변경 = id, 해제 = null).
4. 성공 시 모달을 닫고 토스트 「部署を登録しました。」/「部署を更新しました。」를 표시한 뒤 목록과 요약을 다시 조회한다.

### 소속 사원 확인 (所属社員確認 모달)

- 所属社員数 옆 [確認] 클릭 시 해당 부서의 모달(큰 폭)을 연다. 0명 부서·未所属도 열 수 있다. 닫은 뒤 목록의 스크롤 위치·검색어는 유지된다.
- 헤더: 사람 아이콘 + 제목 「所属社員確認」, 제목 아래 `Badge` info 「{部署名} / 所属社員 N名」(긴 부서명은 1줄 말줄임, 전체는 `title`), 닫기(X).
- 본문 상단: 「対象社員 N名」 + 검색 입력(`SearchInput`, placeholder 「社員名で検索」, `sm` 미만은 전폭).
- 표: 社員番号 / 氏名(아바타 아이콘 + 이름) / 部署(대상 부서명 `Badge` info) 3열. 활성 사원만, 사원번호 오름차순. 표 영역은 화면 높이 640px 이상에서 최대 높이 50dvh로 내부 스크롤하고 헤더 행을 고정한다(그보다 낮은 화면은 모달 본문 스크롤만 사용). 모달 안에 페이지네이션은 없다. footer [閉じる].
- 조회: 열 때 API-DEPT-008을 `limit=100`(상한)으로 1페이지 조회한 뒤, `totalPages`만큼 나머지 페이지를 병렬 조회해 부서의 전체 활성 소속 사원을 모은다(수집 중 중복은 id로 제거). 모달을 연 시점의 스냅샷이며, 열려 있는 동안의 변경은 반영하지 않는다.
- 검색: API-DEPT-008에 이름 검색 파라미터가 없으므로 모은 전체 목록을 클라이언트에서 필터한다. 氏名 부분 일치, 대소문자·공백(반각·전각) 무시. 서버 재조회·화면 새로고침은 없다.
- 인원 수(배지·「対象社員」): 검색과 무관하게 부서 전체 소속 활성 사원 수. 조회 완료 전에는 목록의 `memberCount`로 표시한다.
- 상태(모두 표 헤더 유지, 행 영역에 표시): Loading: 스켈레톤 / Empty: 「所属している社員はいません。」 / 검색 결과 없음: 「条件に一致する社員は見つかりませんでした。」 / Error: `SectionError`(재시도)
- 404 NOT_FOUND: 모달을 닫고 서버 `message` 토스트(1회), 목록·요약 다시 조회.
- 범위 밖: 入社日 열은 표시하지 않는다(사용자 결정). 役職·連絡先 열은 DB에 컬럼이 없어 표시하지 않으며(빈 열·placeholder 없음), DB 추가와 함께 별도 작업으로 다룬다.

### 삭제

- 판단 기준은 `memberCount`(활성 사원 수)뿐이다. 책임자 지정 여부는 영향이 없다.
- `memberCount > 0` 행의 [削除]: 버튼은 활성 상태이며, 클릭하면 API를 호출하지 않고 에러 토스트 「所属する社員が存在するため、部署を削除できません。」를 표시한다.
- `memberCount = 0`: 확인 모달(제목 「部署の削除」)을 연다.
  - 본문 「部署「{name}」を削除しますか？」
  - `inactiveMemberCount > 0`이면 안내 「無効の社員 {n} 名は「未所属」部署に移動されます。」를 추가한다(0이면 표시하지 않음).
  - footer: [キャンセル] [削除する]
- 성공(204) 시 모달을 닫고 토스트 「部署を削除しました。」를 표시한 뒤 목록과 요약을 다시 조회한다. 현재 페이지의 마지막 1건을 삭제했고 2페이지 이상이면 이전 페이지로 이동한다.

## 6. 유효성 검증

| 조건 | 메시지 |
|---|---|
| 部署コード 필수 | 部署コードを入力してください。 |
| 部署コード 영숫자·하이픈 1~20자 | 部署コードは半角英数字とハイフンで20文字以内で入力してください。 |
| 部署名 필수 | 部署名を入力してください。 |
| 部署名 100자 이내 | 部署名は100文字以内で入力してください。 |
| 説明 500자 이내 | 説明は 500 文字以内で入力してください。 |

- 部署責任者는 후보 선택(또는 비움)만 가능하므로 클라이언트 형식 검증은 없다(서버 INVALID_MANAGER로 최종 판단).
- 필드 오류는 해당 필드 아래에 표시하고 `aria-invalid`를 붙인다.

## 7. API

| 기능 | API |
|---|---|
| 부서 목록 | `GET /admin/departments` (API-DEPT-002) — Query: `name`, `sort`, `order`, `page`, `limit=20`(`sort`·`order`는 항상 전송) |
| 부서 요약 | `GET /admin/departments/summary` (API-DEPT-007) |
| 소속 사원 목록 | `GET /admin/departments/:id/members` (API-DEPT-008) — Query: `page`, `limit=100`(전체 페이지 수집) |

| 부서 등록 | `POST /admin/departments` (API-DEPT-004) |
| 부서 수정 | `PATCH /admin/departments/:id` (API-DEPT-005) |
| 부서 삭제 | `DELETE /admin/departments/:id` (API-DEPT-006) |

|---|---|
| 409 DUPLICATE_DEPARTMENT_CODE | 部署コード 필드 아래에 서버 `message` 표시(모달 유지) |
| 409 DUPLICATE_DEPARTMENT_NAME | 部署名 필드 아래에 서버 `message` 표시(모달 유지) |
| 400 INVALID_MANAGER (등록·수정) | 部署責任者 필드 아래에 서버 `message` 표시(모달 유지), 후보 다시 조회 |
| 409 PROTECTED_DEPARTMENT (수정·삭제) | 모달을 닫고 서버 `message` 토스트, 목록 다시 조회 |
| 409 DEPARTMENT_HAS_MEMBERS (삭제) | 확인 중 사원이 배정·재활성화된 경우. 모달을 닫고 서버 `message` 토스트, 목록 다시 조회 |
| 404 NOT_FOUND (수정·삭제·소속 사원) | 모달을 닫고 서버 `message`(「部署が見つかりません。」) 토스트, 목록 다시 조회 |
| 403 FORBIDDEN (수정·삭제) | 모달을 닫고 서버 `message` 토스트, 목록 다시 조회 |

## 9. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- Loading: 목록 영역에 스켈레톤, 요약 카드 자리에 스켈레톤
- Empty: 条件に一致する部署がありません。
- Error(조회 실패): 목록 영역에 `SectionError`. 요약 실패는 수치를 「—」로 표시

## 10. 완료 조건

- 부서 목록을 부서명으로 검색하고, 部署名·所属社員数·更新日로 정렬할 수 있다.
- 부서 수(未所属 제외)와 전체 활성 사원 수를 확인할 수 있다.
- 부서를 등록·수정할 수 있고(설명·부서 책임자 포함), 코드·이름 중복이 방지된다. 책임자는 활성 사원만 지정할 수 있다.
- 部署詳細 모달에서 부서 상세를, 所属社員確認 모달에서 부서별 소속 사원을 확인·검색할 수 있다.
- 활성 사원이 없는 부서만 삭제할 수 있고, 비활성 사원은 未所属으로 이동된다.
- 未所属 부서는 수정·삭제할 수 없다.
- 관리자가 아닌 사용자의 접근이 차단된다.
