# SCR-010: 부서 관리

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-010 |
| 화면명 | 부서 관리(部署管理) |
| URL | /admin/departments |
| 접근 권한 | 관리자 |
| 관련 요구사항 | FR-DEPT-001 |

## 2. 화면 목적

관리자가 부서를 조회·검색하고, 등록·수정·삭제한다.

## 3. 검색 조건

`Card`(제목 「検索条件」) 안에 배치한다. `sm` 이상은 1행, 미만은 세로 배치.

| 요소 | 타입 | 설명 |
|---|---|---|
| 部署コード | Input | 부분 일치, 대소문자 무시, 최대 20자 |
| 部署名 | Input | 부분 일치, 대소문자 무시, 최대 100자 |
| 検索 버튼 | Button | 검색 실행(문구는 「検索」, 03 목록 규칙) |
| 新規登録 버튼 | Button | 페이지 제목 「部署管理」 우측. 등록 모달 열기 |

## 4. 목록 구성

`Card`(제목 「部署一覧」). 부서 코드 오름차순(서버 정렬). 표 위에 보조 문구 「所属社員数は有効な社員のみを数えます。」를 표시한다.

| 컬럼 | 설명 |
|---|---|
| 部署コード | 부서 코드 |
| 部署名 | 부서명. 시스템 부서(`isSystem = true`, 未所属)는 옆에 `Badge` neutral 「システム」 |
| 所属社員数 | 활성 사원 수(`memberCount`), 「N名」, 우측 정렬 |
| 更新日 | 수정일(Asia/Tokyo 날짜) |
| 操作 | [編集][削除]. 열 제목은 화면에 보이지 않는다(스크린리더 전용). 시스템 부서 행에는 표시하지 않는다 |

- [編集][削除] 버튼의 접근성 이름: 「部署「{name}」を編集」「部署「{name}」を削除」
- `md` 미만 폭에서는 표 대신 같은 항목의 카드 목록으로 표시한다(SCR-008과 같음).

## 5. 동작 명세

### 조회

1. 화면 진입 시 URL Query(`code`, `name`, `page`)의 조건으로 조회한다(없으면 조건 없음, 1페이지).
2. 검색 조건 입력 후 [検索] 클릭 시 앞뒤 공백을 제거하고 1페이지로 이동한다.
3. 페이지네이션(20건)과 검색 조건 유지는 03 공통 규칙을 따른다. 결과가 0건이어도 전체 건수가 있으면(범위 밖 페이지) 페이지네이션을 표시한다.

### 등록·수정 (등록·수정 모달)

1. [新規登録] 또는 [編集] 클릭 시 모달을 연다(제목 「部署の登録」/「部署の編集」). 수정 시 현재 값을 채운다. 열 때마다 입력값을 초기화한다.

   | 항목 | 타입 | 필수 | 설명 |
   |---|---|---|---|
   | 部署コード | Input | O | placeholder 「例: DEV」, 안내 「半角英数字とハイフン、20文字以内」. 서버가 대문자로 정규화한다 |
   | 部署名 | Input | O | 최대 100자 |

2. footer: [キャンセル] [登録する]/[保存する]. Enter로도 제출할 수 있다.
3. 입력값 검증(앞뒤 공백 제거 후) → 등록 `POST` / 수정 `PATCH`(코드·이름 모두 전송)
4. 성공 시 모달을 닫고 토스트 「部署を登録しました。」/「部署を更新しました。」를 표시한 뒤 목록을 다시 조회한다.

### 삭제

- 판단 기준은 `memberCount`(활성 사원 수)뿐이다.
- `memberCount > 0` 행의 [削除]: 버튼은 활성 상태이며, 클릭하면 API를 호출하지 않고 에러 토스트 「所属する社員が存在するため、部署を削除できません。」를 표시한다.
- `memberCount = 0`: 확인 모달(제목 「部署の削除」)을 연다.
  - 본문 「部署「{name}」を削除しますか？」
  - `inactiveMemberCount > 0`이면 안내 「無効の社員 {n} 名は「未所属」部署に移動されます。」를 추가한다(0이면 표시하지 않음).
  - footer: [キャンセル] [削除する]
- 성공(204) 시 모달을 닫고 토스트 「部署を削除しました。」를 표시한 뒤 목록을 다시 조회한다. 현재 페이지의 마지막 1건을 삭제했고 2페이지 이상이면 이전 페이지로 이동한다.

## 6. 유효성 검증

| 조건 | 메시지 |
|---|---|
| 部署コード 필수 | 部署コードを入力してください。 |
| 部署コード 영숫자·하이픈 1~20자 | 部署コードは半角英数字とハイフンで20文字以内で入力してください。 |
| 部署名 필수 | 部署名を入力してください。 |
| 部署名 100자 이내 | 部署名は100文字以内で入力してください。 |

필드 오류는 해당 필드 아래에 표시하고 `aria-invalid`를 붙인다.

## 7. API

| 기능 | API |
|---|---|
| 부서 목록 | `GET /admin/departments` (API-DEPT-002) — Query: `code`, `name`, `page`, `limit=20` |
| 부서 등록 | `POST /admin/departments` (API-DEPT-004) |
| 부서 수정 | `PATCH /admin/departments/:id` (API-DEPT-005) |
| 부서 삭제 | `DELETE /admin/departments/:id` (API-DEPT-006) |

## 8. 권한 및 예외

- ADMIN만 접근할 수 있으며 서버에서도 검증한다. 비관리자의 진입은 03 공통 규칙(`/admin/*`)대로 처리한다.

| 응답 | 처리 |
|---|---|
| 409 DUPLICATE_DEPARTMENT_CODE | 部署コード 필드 아래에 서버 `message` 표시(모달 유지) |
| 409 DUPLICATE_DEPARTMENT_NAME | 部署名 필드 아래에 서버 `message` 표시(모달 유지) |
| 409 PROTECTED_DEPARTMENT (수정·삭제) | 모달을 닫고 서버 `message` 토스트, 목록 다시 조회 |
| 409 DEPARTMENT_HAS_MEMBERS (삭제) | 확인 중 사원이 배정·재활성화된 경우. 모달을 닫고 서버 `message` 토스트, 목록 다시 조회 |
| 404 NOT_FOUND (수정·삭제) | 모달을 닫고 서버 `message`(「部署が見つかりません。」) 토스트, 목록 다시 조회 |
| 403 FORBIDDEN (수정·삭제) | 모달을 닫고 서버 `message` 토스트, 목록 다시 조회 |

## 9. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- Loading: 목록 영역에 스켈레톤
- Empty: 条件に一致する部署がありません。
- Error(조회 실패): 목록 영역에 `SectionError`

## 10. 완료 조건

- 부서 목록을 코드·이름으로 검색할 수 있다.
- 부서를 등록·수정할 수 있고, 코드·이름 중복이 방지된다.
- 활성 사원이 없는 부서만 삭제할 수 있고, 비활성 사원은 未所属으로 이동된다.
- 未所属 부서는 수정·삭제할 수 없다.
- 관리자가 아닌 사용자의 접근이 차단된다.
