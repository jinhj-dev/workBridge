# SCR-008: 전체 근태 관리

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| Screen ID | SCR-008 |
| 화면명 | 전체 근태 관리 |
| URL | /admin/attendance |
| 접근 권한 | 관리자 |
| 관련 요구사항 | FR-ATT-004, FR-ATT-005 |

## 2. 화면 목적

관리자가 전체 사용자의 근태 기록을 조회하고, 퇴근 누락 등 잘못된 기록을 수정한다.

## 3. 검색 조건

| 요소 | 타입 | 설명 |
|---|---|---|
| 이름 | Input | 사원 이름 부분 일치 |
| 부서 | Select | 전체 / 부서 목록. 부서 목록 조회에 실패하면 "전체"만 표시 |
| 시작일 | Date Picker | 조회 시작일 (필수, 기본: 이번 달 1일) |
| 종료일 | Date Picker | 조회 종료일 (필수, 기본: 오늘) |
| 근무 상태 | Select | 전체 / 근무 중 / 퇴근 완료 / 퇴근 누락 |
| 조회 버튼 | Button | 검색 실행 |

- 미출근(기록 없음)은 근태 기록 목록의 대상이 아니다. 오늘 미출근 인원은 대시보드(SCR-002) 전체 현황에서 확인한다.

## 4. 목록 구성

| 컬럼 | 설명 |
|---|---|
| 근무일 | 근무 날짜 (요일 포함) |
| 사원명 | 직원 이름. 클릭 시 `/admin/users/:id`로 이동 |
| 부서 | 소속 부서 |
| 출근 시간 | 출근 시간 |
| 퇴근 시간 | 퇴근 시간. 없으면 `—` |
| 근무 시간 | 총 근무 시간. 없으면 `—` |
| 상태 | 근무 중 / 퇴근 완료 / 퇴근 누락 |
| 편집 | [編集](`EditButton`, primary outline + 鉛筆 아이콘) — 근태 수정 모달 열기. 열 제목은 스크린리더 전용 「編集」(2026-11-14 「修正」→「編集」, 사용자 결정 Q3) |

- `md` 미만 폭에서는 표 대신 같은 항목의 카드 목록으로 표시한다.

## 5. 동작 명세

### 조회

1. 화면 진입 시 기본 조회 기간으로 조회한다.
2. 검색 조건을 입력한다.
3. 조회 버튼 클릭
4. 전체 근태 API 호출
5. 조회 결과 표시

### 정렬

- 기본 정렬은 근무일 내림차순
- 동일 날짜는 사원명 오름차순

페이지네이션과 검색 조건 유지는 03 공통 규칙을 따른다.

### 근태 수정

1. [編集](접근 이름 「{name}さんの{workDate}の勤怠を編集」. 2026-11-14 버튼 문구 「修正」→「編集」, UI_BUTTON_PATTERNS B19. 모달 제목·설명·확인문·토스트와 확인 단계 [修正する]는 그대로 — Q1) 클릭 시 근태 수정 모달 표시(폭 `lg`, 시계 제목 아이콘, 제목 「勤怠の修正」, 제목 아래 설명문 「出勤・退勤時刻を修正します。」). 입력 단계 본문은 위에서부터 서버 오류 `Notice`(있을 때) → 읽기 전용 요약(`ReadOnlySummary`: 社員名·勤務日) → `FormTable`(出勤時刻 필수 표시 `*`·`aria-required` / 退勤時刻 + 힌트 「退勤時刻は空欄にできます。」). 열린 직후 出勤時刻에 포커스
2. 출근 시간, 퇴근 시간 입력(근무일 기준 일시)
3. 저장 클릭 후 확인(같은 모달 안 확인 단계 「勤怠を修正しますか？」, [戻る] [修正する]. 확인 단계로 바뀌면 [修正する]에 포커스, [戻る]나 400 INVALID_TIME_RANGE로 입력 단계에 돌아오면 出勤時刻에 포커스). 제출 중에는 닫기(X)·Esc로 닫을 수 없다
4. 근태 수정 API 호출
5. 성공 시 토스트 "근태가 수정되었습니다."를 표시하고 목록 갱신

## 6. 유효성 검증

| 조건 | 메시지 |
|---|---|
| 시작일·종료일 필수 | 조회 기간을 입력해주세요. |
| 시작일 ≤ 종료일 | 시작일은 종료일보다 늦을 수 없습니다. |
| 최대 조회 기간 이내(FR-ATT-004) | 조회 기간은 최대 1년입니다. |
| (수정) 출근 시간 필수 | 출근 시간을 입력해주세요. |
| (수정) 퇴근 시간 > 출근 시간 | 퇴근 시간은 출근 시간보다 늦어야 합니다. |

부서는 등록된 부서 목록에서만 선택한다.

URL Query의 기간이 형식은 맞지만 순서 또는 최대 기간 규칙을 위반하면 기본 기간으로 바꾸지 않고 해당 검증 메시지를 표시하며, 목록 카드를 숨기고 API를 호출하지 않는다.

## 7. API

| 기능 | API |
|---|---|
| 전체 근태 조회 | `GET /admin/attendance` (API-ATT-005) — Query: `name`, `departmentId`, `startDate`, `endDate`, `status`, `page`, `limit` |
| 근태 수정 | `PATCH /admin/attendance/:id` (API-ATT-006) |
| 부서 목록 | `GET /departments` (API-DEPT-001) |

## 8. 권한 및 예외

- ADMIN만 접근할 수 있으며 서버에서 ADMIN 권한을 검증한다.

| 응답 | 처리 |
|---|---|
| 400 INVALID_DATE_RANGE | 검증 메시지와 같은 문구 |
| 400 INVALID_TIME_RANGE | 모달 안에 "출퇴근 시간을 확인해주세요." |
| 404 NOT_FOUND (수정) | 근태 기록을 찾을 수 없습니다. (목록 다시 조회) |

## 9. 상태 처리

공통 규칙(03 Common UI Rules)을 따른다.

- Empty: 조건에 맞는 근태 기록이 없습니다.

## 10. 완료 조건

- 전체 사용자의 근태를 조회할 수 있다.
- 이름, 부서, 기간, 상태별 검색이 가능하다.
- 퇴근 누락 기록을 찾아 수정할 수 있다.
- 페이지네이션과 정렬이 정상 작동한다.
- 일반 직원의 접근이 차단된다.
